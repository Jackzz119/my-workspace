# 成本与周期速查

## 范围纪律（独立项目第一死因是范围失控）
- **一次只赌一个创新点**：玩法/美术/叙事/商业模式里挑一个创新，其余用成熟方案
- **非目标清单与功能清单同等重要**，写进设计文档并对每次"顺便加个"说不
- 内容量 = (玩家消耗速度 × 目标时长) ÷ 复用系数——先算再承诺；系统深度（组合）比内容广度（关卡数）便宜
- 砍功能优先级：先砍"锦上添花的系统"，再砍"内容量"，最后才动"核心循环打磨时间"（顺序反了=项目死）

## 阶段模型（倒排里程碑）
1. **纸面/一发 Demo（1-7 天）**：验证核心动词好不好玩——oneshooter 管线
2. **垂直切片（2-8 周）**：一段完整体验打磨到成品质感，回答"值得做完吗"+给发行/众筹看
3. **横向铺量**：切片验证后才铺内容；美术管线组件化（大图少、组件多、程序化零成本层）
4. **Demo 公开版 → Next Fest → EA/1.0**：见 marketing.md 的时间轴

## 成本粗算（solo/小团队网页或PC独立游戏）
- 时间是最大成本：solo 全职一年 ≈ 机会成本 = 你的年薪
- AI 美术管线（codex/fal/Tripo）把素材成本从"外包 $50-200/张"压到"迭代时间"，但**风格统一监管**成为新成本（monet 的职责）
- 音频常被低估：预留预算或用合成音（WebAudio/自动化工具）起步
- 本地化、QA、商店素材（胶囊图/预告片）各占 1-2 周，别在排期里漏掉

## 排期经验法则
- 一切估时 ×2 仍会超；deadline 定在"可对外承诺日期"前留 20% 缓冲
- 每周必须有可玩构建；连续两周没有=红色警报
- "打磨"要有清单和轮数上限（如 UI 扫描两轮），否则无限膨胀

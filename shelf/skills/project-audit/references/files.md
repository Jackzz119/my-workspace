# 模块：文件与目录整理（files）

只在跑文件与目录整理模块或复验相关清理时加载。范围是整个项目：自有源码、文档、配置、测试、脚本、资源都算，不只是文档目录。
本模块只管文件的去留与组织：文档正文的精简归提示词与文档模块，代码边界归代码审核模块，测试的去留归测试与 CI 成本模块。

## 1. 用途判定与清理

- 给文件确定用途、使用者、权威性、引用和生命周期。找废弃、重复、临时、生成或已被取代的文件。
- 清理前检查静态和动态引用、路由约定、构建/导出配置、发布脚本、人工流程、外部契约及资源元数据。
  无搜索命中只是一条线索；完整删除证据要求见 common.md §3。
- 已授权且证据充分的冗余直接删除，不改成长期“待清理”堆积；不确定项保留并说明缺少哪条证据。

## 2. 目录与命名

检查目录是否易发现、命名一致、职责清楚、资源与消费者靠近。
文件移动后的引用核对同样按 common.md §3：文本链接、构建/运行引用和引擎资源引用都要验。

## 3. 交付

删除/合并/保留清单，每项写用途判定、引用证据、保留的权威源、恢复依据和验证结果；目录与命名的前后对照。
用文件路径和提交定位被移除的原文，说明理由和恢复路径；报告不复制代码/长文，原始证据按需加载。

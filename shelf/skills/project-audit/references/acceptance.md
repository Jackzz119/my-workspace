# 验收期：处理总报告的批注

总报告发出后，用户的批注就是本轮的验收期，不另开一轮。读批注、写回复页、清批注按批注报告工具（如 `annotated-report`）的流程，
包括回复按功能 / 模块归类、跨轮怎么收束；本文件只管审核这边要多做的。

## 1. 开工

- 先读 `INDEX.md` 与本轮 `00-log.md`（含「七、验收」已有的小节与断点），再读这一轮的全部批注与附图。
- 上一会话留在工作区或暂存区的改动，先按宿主协议处理（如单独提交并写明来源），再开始这一轮的改动。
- 在「七、验收」新开一小节「批注第 N 轮」，开工前就写好：条数、分组、新决定编号、分工、断点；之后随做随存（[reference.md](../reference.md) §9）。

## 2. 归类与编号

- 按功能 / 模块分组（如：审核的某一步、某个产品模块、UI 工作包、技能与协议），每组写清覆盖哪几条批注；回复页按同样的分组写。
- 每条判一类：问题（要答）、决定（要记）、改动（本期做）、本期不做（转交接档或待办）。
- 新决定的编号由主线程一次分好、写进日志，子线程共用，不各自编号；决定写进项目的决定清单与待办，不只留在审核目录。

## 3. 执行

- 改动多时按文件互斥分给子线程并行：每个子线程写明负责哪些文件、哪些别人在改不能碰；子线程不提交，主线程核对、过门禁、提交。
- 技能与协议只改批注里用户明确要的；协议按其修改授权，技能按其修改规则。
- **本期不做的转交接档**（如还没排期的 UI 工作包）：放进项目的会话存档目录（只新建本轮的交接档，不读、不改已有的存档），
  按 `intj` 的交接规则写——一包一份，
  附图与资源链接，正文用工作包（依据、改法、验收、别踩的线），不另写一套；写明执行方要自己调研再动手，
  并在报告里说明与交接档相比改了什么。没有 `intj` 时写进任务来源，附同样的内容。建不建外部任务单、什么时候放行由用户定。

## 4. 收尾清单

这一轮批注处理完，逐项打勾，记进「七、验收」：

- [ ] 门禁全绿（按项目：类型、lint、测试、构建）
- [ ] 按宿主协议提交、开 PR、合并（合并前的校验照协议）
- [ ] 改过的技能与协议按宿主的同步机制推回共享源（如货架）
- [ ] 用户确认过的记忆删除已执行
- [ ] 回复页已发；处理过的批注与附图已清（页面属于别的账号、清不了时在回复里说明）
- [ ] `INDEX.md` 本轮的状态、`FINDINGS.md` 受影响的行、`00-log.md`「七、验收」已更新
- [ ] 本地兜底环境与临时文件已清

## 5. 额度中途用尽

- 断点写在当前「批注第 N 轮」小节里，覆盖式更新：处理到哪几组、哪些子线程在途（负责的文件、产出路径、写到哪）、
  哪些还没派、主线程余下的收尾项。
- 续跑的会话先核对工作区与断点；换会话、换 worktree、换账号与在途子线程的处理同 [reference.md](../reference.md) §9。

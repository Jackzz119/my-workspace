# 第一步：文档、冗余文件与目录整理

只在第一步、文档专项或文档精简复验时加载。范围是整个项目，重点检查 AI 上下文（协议、技能、项目文档），而不是只检查文档目录。

## 1. 用途判定与清理

- 给文件确定用途、使用者、权威性、引用和生命周期。找废弃、重复、临时、生成或已被取代的文件。
- 清理前检查静态和动态引用、路由约定、构建/导出配置、发布脚本、人工流程、外部契约及资源元数据。
  无搜索命中只是一条线索；完整删除证据要求见 [reference.md](../reference.md) §3。
- 已授权且证据充分的冗余直接删除，不改成长期“待清理”堆积；不确定项保留并说明缺少哪条证据。
- 检查目录是否易发现、命名一致、职责清楚、资源与消费者靠近；本步处理文件组织，第二步再处理代码边界。

## 2. 文档精简与压缩验收

- 精简重复说明、冗长叙述和过时状态，保留独有决策、强制规则、术语、未解决问题及恢复所需信息。
  同一事实留一个权威正文，其余用短摘要和链接；语义重复须人工核对，不能机械截字数。
- AI 活文档以当前项目形状、有效规则和未来待办为主，删除已完成流水、作废方案与无继续价值的历史。
- 每份适用文档以本轮执行前版本为基线，目标为精简后不超过原文 **2/3（至少减少 1/3）**；同时报告文档族总量。
  有可靠 tokenizer 时用同一编码，否则用 UTF-8 bytes 并另列行数，不冒充 token。不能靠挪到另一份常驻文档、
  去空格或删关键条件凑比例。已足够短或包含不可删契约的文档逐项说明例外；未达标不得写成已达标。
- TODO 保留未完成/进行中/阻塞事项及其 ID、依赖和验收条件，删除已完成历史；PROJECT 只留现状、必要原因与索引。
  其他协议或唯一正文已有的内容改短链接，确实独有且有效的项目条件仍保留。受保护文件与冻结原件按既有边界处理。
- **防回胀**：只压一次的文档会长回去。把「只写现状、决定只引编号、过程交给 git」写进负责写这些文档的技能或协议，
  再加自动检查（每份活文档的体积预算、链接与锚点）；下一轮复审实测有没有回胀。
- **固定检测：常驻文档的上下文成本形态（每轮第一步必查）**。量出启动必读与高频文档族的大小
  （UTF-8 bytes，另列行数或统一 token 口径），逐份核对三条并记录结果：
  ① 已完成流水是否已从活文档清掉（删掉，或移入不在启动必读里的归档）；
  ② 40KB+ 的正文文档开头是否有「摘要与目录」（≤15 行：现状一段 + 每节一行「什么时候读」），能否支撑选读；
  ③ 无法整读（约 100KB+）的是否按节分册、本体只留索引，且节编号不重排、既有「§N」引用仍可寻址。
  缺哪条在本步授权内补齐，超出授权的列入建议；三条全过也要写入报告作为基线。

## 3. 提示词与协议审核

- 范围：根协议及其副本、全部技能（入口、参考、脚本说明）、技能登记表、项目文档里每会话必读的部分、可读的 agent 记忆。
- 查写给旧模型的过时写法、互相矛盾或与仓库现实不符的规则、重复强调、失效引用与导入、成对协议之间的不等义。
  有 prompt-audit 类工具时按它的流程走；宿主 agent 的加载规则（技能目录、协议文件优先级、导入语法）上网核实当前版本。
- **固定检测：agent 持久记忆（每轮第一步必查）**。宿主 agent 有跨会话记忆时（如 Claude Code 的 auto-memory：
  `~/.claude/projects/<项目>/memory/` 下的 `MEMORY.md` 索引 + 各条主题文件，同一仓库的所有 worktree 共用一份），
  读索引和全部条目，按项目协议对记忆的约束逐条判去留：项目里已有等价记录的删；与项目矛盾的以项目为准删；
  属于项目知识的先迁入对应文档再删；用户明确要求隐藏、不入库的保留。量出索引大小，核对是否超过宿主的开场加载上限
  （Claude Code 只加载 `MEMORY.md` 前 200 行或前 25KB，超出部分静默失效）。删除前先备份、把清单交用户确认；
  报告会入库，只写条目名、去向与理由，**隐藏规则不写内容**。宿主没有持久记忆时记「不适用」。
- 协议与技能受修改授权保护时，按其授权处理；要用户定的列成决定项，每项附推荐与不回答时的默认。

## 4. 测试与 CI 成本

- 全盘检查单元/集成/UI 测试、临时验证脚本和实际 CI 入口，记录每项保护的行为、是否入 CI、重复覆盖与实测耗时。
- 已完成使命的一次性测试、只钉细微外观/实现细节且无功能保障的断言、已被等价覆盖的重复测试可以删除或合并；
  稳定代码本身不是可删证明。保留仍能捕获业务回归、权限/数据隔离、金额、输入校验、幂等、数据完整性与关键交互问题的有效覆盖。
- 删前明确失去哪些断言、剩余哪里覆盖；删后运行受影响及仍适用的测试。区分测试执行、导入/初始化、构建和 CI 调度耗时，
  比较相同环境与缓存条件；不能把测试数减少直接写成 CI 提速，也不靠跳过失败测试过关。

## 5. 交付

删除/合并/保留清单、逐文档压缩率与例外、未完成事项保真核对、提示词审核结论与决定项、测试覆盖取舍和耗时对照、
文档权威关系与链接验证。用文件路径和提交定位被移除的原文，说明理由和恢复路径；报告不复制代码/长文，原始证据按需加载。

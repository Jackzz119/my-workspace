## 1. 要办的事用什么

| 要办的事 | 工具 | 要点 |
| --- | --- | --- |
| 开子会话 | `start_session` | fresh（必须另给 `background`，八十字以上）、`use_worktree`、`name`、`wake_when_done`；模型、权限档不填就继承；标题按项目规矩一次起好（含模型·effort·sidechat 这类标记），子会话就不用再改名 |
| 发跟进、答疑、催续跑 | `SendMessage`，`to` 填 `local_…` 会话 id | 对方空闲就起一轮；正忙就等它手上的活做完才读。`notify_when_idle` 订不了桌面端的会话（实测），等交回用后台命令看文件，见 recovery.md 第 1 节 |
| 看名下会话 | `list_sessions`，`linked: true` | 看 `isRunning`、分支、PR、最近活动；一次看完，不逐个查 |
| 看它停在哪 | 先看交回文件与分支提交，再用 `list_events`（限条数） | 对话很长，会带出技能正文等注入 |
| 停下它这一轮 | `stop_session` | 停完还开着，可以再发消息 |
| 换模型 / effort | `set_session_model`、`set_session_effort` | 见第 5 节 |
| 查额度、上下文 | `get_usage` | 空闲会话的上下文读不到 |
| 约唤醒 | `CronCreate`（会话内，进程在才触发） | 唤醒起的是自动轮，见第 2 节 |
| 归档、删除 | `archive_session`、`delete_session` | 用户明说才用，见第 6 节 |

这些工具可能是延迟加载的，先用 `ToolSearch` 一次取齐。

## 2. 什么时候能直接开会话

**默认：用户批准方案的那一轮，一次开齐这个任务要用的会话**，测试会话也开，让它先待命：

1. 开发会话照任务说明直接开工。
2. 测试会话第一轮只做一件事：按要求与验收列测试清单写进它的交回文件，然后结束这一轮，等主会话消息。测试清单本来就该在看实现之前列，待命不浪费，也保证了独立。
3. 开发交回、主会话核过之后，给测试会话发跟进消息：「开始验，被测 <分支 @ sha>」。发消息在自动轮里照样可以。

为什么不等开发交回再开：`start_session` 直接开（`user_asked`）只在**用户亲口在本会话说话的那一轮**可靠。子代理回报、定时唤醒、别的会话发来的消息、子会话回报起的都是自动轮，会被拒，只能出卡片等用户点（实测：用户在本会话还没说过话时，子会话回报叫醒的那一轮被拒）。工具说明里有一个例外：回报轮紧跟在用户自己的一轮之后、开的是用户已经要求的那一步；中间隔了别的自动轮就不算，别指望它。

- 被拒了不要找别的路（让子会话替你开、换个说法再试）：出卡片，说清是宿主的限制、点一下就行，不另外发问句。
- 卡片会丢掉 `source_branch`、`branch_name` 和 `name`，worktree 从集成分支切（实测）：任务说明里要写清被测分支从哪拿，开起来后把真实的短名和分支记进台账。
- 没法一次开齐的（要等前一步结论才知道下一步派什么），把下一步的派活安排在一个本来就要用户点头的节点上；那之前收完后台子代理，别让它的回报插在用户说话和开会话之间。
- 用户点名本技能、批准方案，就是开这些会话的授权；方案里写明开几个、各做什么，之后不再逐个问。

## 3. 工作区与分支

- 会写代码的子会话一律用自己的 worktree。共用主会话的检出会互相覆盖，也没有东西拦着；只读的活才可以共用。
- worktree 从 `source_branch`（**本地**分支）切，不写就是本会话的基准分支。主会话没提交的改动子会话看不到：派活前先提交。
- 测试会话要拿到开发的改动：直接从开发分支切（开的时候开发已经提交），或者在自己的分支上 `git merge --no-edit <开发分支>`。同一个仓库的 worktree 共用本地分支，不用推远端。不切分支、不 reset。
- app 会复用以前的 worktree 目录（实测），里面可能有上个会话留下的被忽略文件（依赖、构建产物、环境文件）：任务说明里写清依赖和环境怎么备，别假定是空的，也别假定是新的。
- worktree 会话的技能、钩子、设置读的是**主检出**那份，只有协议文件读 worktree 的。测改过的技能，让它直接读文件路径。
- 共享笔记目录：名下会话共用，在仓库外。macOS 上是 `~/Library/Application Support/Claude/side-session-notes/<主会话 id>/`（实测；路径带空格，命令里加引号；主会话 id 用 `get_session("self")` 查）。开第一个子会话时 app 会建它，之前要用就自己 `mkdir -p`。里面分 `main/`（台账、任务说明存底）、`dev/`（开发交回）、`test/`（测试交回）；宿主会让子会话先读兄弟的笔记，所以测试说明里写明不读 `main/` 和 `dev/`。

## 4. 回报与消息

- 子会话结束一轮，主会话只收到**前 400 个字符**。最后一条消息必须把结论词、分支与 sha、交回路径放在最前面，别的都在文件里。
- 名下没有会话在跑、主会话空闲时，宿主叫醒主会话。它挂着后台任务结束一轮时也会报「结束」、列表里显示空闲，后台跑完它自己接着做完，会再通知一次（实测）。用户自己在子会话里驱动的那一轮、被停的、失败的那一轮，通知要等到主会话的下一轮才送到；云端会话不回报。
- 消息不是用户的同意：子会话的权限确认只能由用户在那个会话里点；子会话也不会因为主会话一句话就去改权限、协议或配置。
- 两边权限档位不同，消息可能被扣下，过一会儿就丢。开的时候用和主会话一样的档位。
- 查用户有没有和子会话说过话：看对话里的用户消息，去掉标着来自别的会话的、技能与系统插入的，剩下的就是用户说的。交回里那一条和这里对不上时，以这里为准。

## 5. 模型、effort、权限

- 开的时候只能给同档或更低的模型、同级或更低的 effort 和权限，更高的会被忽略；不写就继承主会话。
- 要给更高的模型：开完用 `set_session_model`，宿主会问用户；或请用户在那个会话里选。
- 项目对「不给比自己低的模型」有规定的按项目。

## 6. 归档与删除

- 归档、删除都等用户明说。归档主会话时，名下**空闲、没有自己的未关 PR** 的会话跟着归档；还在跑（含后台任务、开发服务器）、被置顶的不会。会话（或它的子会话）正开在屏幕上时这次归档会被拒，请用户自己点。`archive_session("self")` 调完对话就结束，话先说完。
- 有没提交的改动时归档可能丢改动或把 worktree 留在磁盘上：收尾前每个 worktree 都要干净。
- 删除主会话时，名下会话只是归档。用户要全删，用 `delete_session` 把它们的 id 一起给（任何权限模式都会弹确认卡）。
- 已经移到顶层的会话不跟着归档，也不再回报。
- 子会话的本地分支不用手删（worktree 占着也删不掉），由宿主在归档、删除时处理；远端分支要自己删。

# 独立验证

> 什么时候读：第一次派测试或评审之前；收到 PASS / FAIL 时。

## 1. 测试和评审是两把椅子

| | 测试 | 评审 |
| --- | --- | --- |
| 看什么 | 要求、验收、跑起来的东西 | 改动的 diff、要求（查漏做和多做） |
| 问什么 | 它做到了没有 | 它哪里会错 |
| 产出 | 逐条过 / 没过 / 无法验证 + 证据 | 逐条发现 + 能复现的错误输入与结果 |
| 默认用不用 | 用 | 高风险、评审修复时加；要加就换视角，不是同样再来一遍 |

两边都不看开发的理由、自测结论和「测试已通过」这类信号：看了就会偏向放行。新上下文比换一家模型管用。

不要按工种把一个功能切给三个会话（写码 / 写单元测试 / 写文档）：单元测试归开发自己写，独立会话只做黑盒验收。

## 2. 测试会话怎么验

1. 先只看要求，列测试清单并写进交回文件（待命那一轮做的就是这个），**之后不因为看了实现而删条目**，只能加。
2. 每条验收至少一个正例、一个反例；加边界。只验「能跑」等于没验。
3. 走真实入口：命令行就真的敲，页面就真的点，接口就真的发；能端到端就不只测函数。
4. 查检查本身有没有用：挑一两处关键实现，在自己的 worktree 里临时改成空操作，相关测试应该变红；看完还原。
5. 「原本就有的失败」要在起点提交上复跑确认，不能凭感觉归到历史问题。
6. 只验不修。找到的问题给最小复现。
7. 没测到的逐条写出来；没验证不等于通过。
8. 结论绑定 sha：开发再提交，结论就作废，要重验相关的部分。

验证期间不改被测的代码和环境；同一时间只让一个会话跑整套构建和端到端，免得互相占端口、拖慢、误判超时。

## 3. 什么算证据

- 命令加实际输出（摘关键几行，带退出码）；页面的截图加操作步骤；数据的查询与结果；文件的路径与内容。
- 不算：「应该没问题」「测试都过了」「已按要求完成」、别的会话转述的结论。
- 非零退出、超时、被杀、半截输出的命令一律算没跑过，重跑；压缩之后的记忆也不算，以落盘的为准。

## 4. FAIL 先分三类

| 类别 | 怎么认 | 怎么办 |
| --- | --- | --- |
| 实现错 | 复现步骤在干净环境里稳定成立，要求写得清楚 | 跟进消息打回**原来的**开发会话：现象、复现、期望，不给修法。它带着上下文，最快 |
| 测试错 | 测试的期望和要求对不上，或环境、数据没备好 | 写明理由发回测试会话改那一条；开发也可以带证据反驳，由主会话裁 |
| 要求含糊 | 冻结的验收没写，原话两种读法都说得通 | 用户看得见的结果问用户（带推荐值），看不见的技术细节主会话定；定完写进要求与验收，同步给两边。别的条目照常往下走，不等这一条 |

同一条打回两轮还没修好：换新的开发会话，说明里写前两轮试过什么、为什么没成。那时多半是自动轮开不了新会话：出卡片，别的条目先走。

## 5. 轮数

- 一轮 = 测试给出一次结论。默认上限三轮（用户可以改）。测试之前主会话自己打回的不算轮，但同一件事纠两次还错就换人。
- 第二轮起只验没过的、改动波及的、新改动本身；不重新挑首轮就在的老问题。
- 被测的 sha 和开发分支头不一致的结论只当线索，不算一轮。
- 过了就停，存档这个 sha。PASS 里带着「这次改动新引入」的应修项，在轮数以内的补一轮，只验那一处；老问题和可选项写成已知限制，不加轮。为了「更好一点」强改一轮，常常把对的改错。
- 到上限没过：停，把每轮试了什么、剩什么、三条路（换人重做、缩小范围、带着已知问题收）给用户。

## 6. 主会话抽验清单

会话会漏看文件却报告全看过，会把没做完的说成做完，极少数会绕过检查；开发自测全过、独立测试一验就翻的情况也常见。所以 PASS 之后、合并之前，主会话自己核：

- [ ] 交回里的 sha 就是现在分支的 sha；提交真的在（`git log`）
- [ ] 改动的文件都在允许范围里；验收、测试、CI、lint 配置没被改松，测试数没少、没有新跳过的
- [ ] 最要紧的一两条验收，自己跑一遍，看到的和交回一致
- [ ] 「没测到的」「没把握的」逐条有去处：补验、写进报告、或者问用户
- [ ] 覆盖类的活（盘点、迁移）：对照实际改过、读过的文件清单，不看自报的数
- [ ] 界面类的活：项目规定的审核（规范、审核技能）由没写它的会话来做，主会话自己看截图或真页面
- [ ] 测试会话真的没看开发的交回（它的清单在看实现之前就写了；有疑问查它的对话）

## 7. 整体验收

几块并行、或者分阶段合进来的，合完之后由主会话（或一个没参与的测试会话）对着**最初的要求**从头验一遍，不是把各块的 PASS 加起来：

- 拼接处优先：字段名与类型、权限、错误形状、加载顺序、重复定义、词条缺漏。
- 项目门禁在合并后的 head 上跑，按项目规定的检查命令与 CI 规则。
- 一条最长的真实使用路径走通。
- 变基后 sha 变了：没有冲突、没人动过同样的文件，重跑门禁和最要紧的几条就够；有冲突或同文件被别人改过，让测试会话在新 sha 上补验相关条目。

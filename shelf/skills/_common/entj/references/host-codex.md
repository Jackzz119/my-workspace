# 宿主手法 · Codex

> 什么时候读：在 Codex（CLI、IDE、桌面 app）当主会话，第一次要开子会话之前。
> 工具名、默认值随版本和模型变，**以工具自己的说明和 `--help` 为准**；不一致就照它做，并在总报告里写一句本技能哪条过时了。
> 本文的来源：learn.chatgpt.com/docs、openai/codex 源码、本机 CLI 帮助与 app 的工具说明，核对于 2026-11-24；没有实跑过整套流程。

## 1. 先定用哪一种「子会话」

Codex 没有一种东西同时满足「干净上下文、自己的工作区、用户看得见、做完自动回报」，开工前先探测手上有哪些工具，再按次序选：

| | 独立线程（app / CLI 的 `create_thread`） | 子 agent（`spawn_agent`） | `codex exec` 子进程 |
| --- | --- | --- | --- |
| 干净上下文 | 是 | **默认不是**：带主会话全部历史，派时写明不带（`fork_turns="none"`） | 是 |
| 工作区 | app 可选 worktree；CLI 继承当前目录 | 和主会话同一个目录，不隔离 | 可指定目录或 worktree |
| 用户看得见 | 是，侧栏里的正式线程 | 能切进去看 | 默认看不见 |
| 结果怎么回 | **不自动回**：主会话自己等、自己读 | 自动送回主会话 | 标准输出、`-o` 文件、JSON |
| 谁授权 | 只认用户本人明说 | 用户说了，或技能写明就行 | 一条命令，按沙箱与审批 |

- **默认**：写代码的开发和独立测试用独立线程加 worktree；工具不在就用 `codex exec --worktree`（默认只读，写代码要给可写工作区的沙箱）；都不行才用子 agent，并告诉用户它和主会话同一个目录，只能一个一个来，不能并行写。
- 子 agent 用在查资料、读代码、只读评审；派的时候写明不带历史、不许再派、交回里列改过的文件。
- 侧聊（side chat）不能当工人。
- 工具缺了又必须让用户看见的：给用户一条新线程的深链接（预填说明，用户点发送），不要假装已经开了。

## 2. 开工时请用户说全的一句

技能和主会话都代替不了用户授权独立线程与互发消息。方案批准时请用户照着说一句，主会话原样记进台账：

> 按 entj 开工：为开发、测试各开新任务，用 worktree；允许主会话给它们发消息，也允许它们回报主会话；验过之后由主会话合并。

## 3. 各阶段怎么落

| 阶段 | 手法 |
| --- | --- |
| 定方案 | 计划模式；方案写成自包含文件（任务说明同理），线程的提示词有长度限制时只传路径 |
| 派活 | 任务说明第一行写「你是主会话 <线程 id> 的子会话」：Codex 认不准自己是不是分出来的。新 worktree 缺被忽略的文件（技能链接、协议副本、环境配置），说明第一步写清怎么补 |
| 等待 | 独立线程不会叫醒主会话：在同一轮里分段等（`wait_threads` 加 `read_thread`），一段几分钟，不短轮询；子 agent 用 `wait_agent` |
| 跟进 | 线程 `send_message_to_thread`；子 agent `followup_task`（会起新一轮）或 `send_message`（只递话）；旧一代工具是 `send_input`；进程用 `codex exec resume <id>` |
| 验证 | 另开一个，规则同 verification.md；只读评审可用 `/review`、`codex review`，真只读用只读沙箱的 `codex exec` |
| 合并 | 没有专用工具，用 git / gh；沙箱可能拦 `.git` 写入，走审批 |
| 清理 | 归档线程会连它的托管 worktree 一起删，归档前先确认提交已合入；远端分支自己删 |

## 4. 做不到的，开工时就说

- **额度恢复后自动接着做**：CLI 和 IDE 没有自我唤醒；app 可以在线程里挂定时，但额度用尽时灵不灵没有依据。写明「额度恢复后请说一声继续」，台账写到换谁都能接上。
- **主会话被叫醒**：独立线程做完不会叫醒主会话，要么在同一轮等，要么用户说一声。
- **授权不随派单传递**：子线程的权限档位可能和主会话不同，卡在审批上只能由用户在那个线程里点。
- **标题**：Codex 不能自己改名，按协议提醒用户改。

## 5. 从 Claude Code 里用 Codex 当一个会话

用户点名要 Codex 参与时：从 Claude 主会话跑 `codex exec`（独立进程、干净上下文、可写报告到文件），它算一个用户看不见的外部工人；额度先查，外部工具有自己的技能就按那个技能。它的结论同样要主会话核。

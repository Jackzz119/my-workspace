# 收尾

> 什么时候读：全部验过、准备合并时；任务中止或放弃时。
> 收尾归主会话。用户说过的话、批准过的方案就是授权；方案里没写的删除、合并、外部动作先问。

## 目录

1. 合并
2. 收尾清单
3. 总报告

## 1. 合并

| | 一个任务一个 PR（默认） | 每块一个 PR |
| --- | --- | --- |
| 什么时候 | 几块合起来才成立；主会话在自己的 worktree 里 | 各块能独立上线；主会话没有自己的工作区；项目规定一事一 PR |
| 子会话做到哪 | 提交到自己的分支，不推送 | 推自己的分支、开 PR，不合并 |
| 主会话怎么合 | 验过的分支并进主会话分支，再推自己的分支、开 PR | 按依赖次序，逐个过项目的合并校验后合 |

默认那种的并法：

- 主会话分支没动过：`git merge --ff-only <子会话分支>`。
- 动过了：`git cherry-pick <起点>..<子会话分支>`，保持线性，合 PR 时不会有合并提交碍事。冲突拿不准的，让那个子会话在自己的 worktree 里变基到主会话分支再交回。
- 不切到子会话的分支，不替它强推，不 reset。并完跑一遍整体验收（verification.md 第 7 节）。
- 宿主可能要求「合并子会话分支之前用户亲口同意」：方案里批准过的就是；没批准过的，列出每条分支的全名问一次。

合进集成分支按项目协议的校验走（CI 在当前 head 上、不落后集成分支、集成分支自己是绿的）。集成分支很忙时早合、少碰索引类文件，免得反复变基。

## 2. 收尾清单

逐条打勾，每条都看真实状态，不凭记忆：

**改动**
- [ ] 每个子会话的活都合入了，或者写明放弃：`closeout-check.mjs` 对名下全部分支退出 0（分支名从会话信息里拷，打错名字会被当成「已清掉」）。报没落进的只是主会话自己的起点提交（变基改写过的）不算，其余逐条查清。脚本跑不了就手工核：`git fetch` 后 `git cherry <集成分支> <子会话分支>` 没有 `+` 行、它的 worktree `git status` 干净、`git ls-remote` 没有同名分支，报告里写明是手工核的
- [ ] 合并后的 head 过了整体验收和项目门禁
- [ ] 索引类文件、任务清单、决定清单、功能文档由主会话一次更新好；子会话交回里「范围外的发现」都有去处

**用户**
- [ ] 台账里每条要求（含途中追加的）都有着落
- [ ] 查过每个子会话里用户说过的话，和交回对得上，进了总报告
- [ ] 攒着的问题问完了，没有悄悄按默认走而没说的

**资源**
- [ ] 名下没有会话在跑；台账登记过的后台任务、开发服务器、端口、容器、浏览器标签都收了（只收登记过的，认不出的不动、写进报告）
- [ ] 每个 worktree 没有未提交、未跟踪的改动（开场钩子改出来的账本也算，让那个会话还原）；没有自己的未关 PR
- [ ] 子会话推过的远端分支删了；临时文件、测试数据、测试账号清了
- [ ] 接手过的交接档按它的规则清了；台账里要长期留的写进了项目文档
- [ ] 主会话约过的唤醒、订过的通知都取消了

**子会话**
- [ ] 交回文件都在、都读过；没有停在半路没处理的
- [ ] 用户打开过、置顶过的会话记下来，归档时它们不会跟着走

## 3. 总报告

按项目的报告规范出**一份**（有报告页规范的出报告页），用户只看它就知道全部：

1. 结论、要用户定的事、最大的风险。
2. 每条要求 → 做到了没有 → 证据（测试结论、主会话抽验）。
3. **每个子会话一节**：派它做什么、交回了什么、主会话核了什么、改了哪些文件（项目要求逐文件贴代码的，连它改的一起贴）、和任务说明不一样的地方、用户和它说过什么。
4. 打回过几轮，各因为什么；无法验证的逐条列。
5. 与方案相比改了什么、为什么。
6. 名下会话清单（链接、状态、分支、worktree）、额度用了多少、被打断几次从哪接上。
7. 流程本身的问题：哪一步和本技能写的不一样，建议怎么改。

## 4. 告诉用户可以归档

资源和子会话两组都打勾之后，用一句话说清：名下哪几个会话、归档主会话会带走哪几个、哪几个不会（还在跑、置顶、开在屏幕上、有未关 PR、已移到顶层）、要删除的话怎么说。归档和删除由用户决定。

用户说「归档」：再看一眼有没有会话又动起来、worktree 还干不干净，然后归档名下会话；要连主会话一起归档的，先把最后的话说完再归档自己（归档后对话就结束了）。宿主会拒绝归档正开在屏幕上或置顶的，被拒就如实说，请用户自己点。用户说「删」：删除会丢对话，先列出名单。

## 5. 中止的任务怎么收

用户叫停、方案走不通、三轮没过决定放弃：

1. 停掉在跑的会话（停那一轮，不是归档）。
2. 有价值的半成品留分支并写进报告；没价值的列出分支与 worktree，问过再清。
3. 收尾清单照走，「合入」换成「写明放弃的原因和留下了什么」。
4. 总报告写做到哪、为什么停、要接着做从哪开始。

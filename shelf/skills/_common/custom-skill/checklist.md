# 技能质量检查清单

> 建完技能自检、审查别的技能都用这一份。每项后面是 reference.md 里对应的节。
> 审查时逐项给「符合 / 必须改 / 建议改 / 不适用」：违反字段约束、授权、安全的算「必须改」，写法问题算「建议改」。第三方技能只审元数据、授权、安全三组，其余记下不改。

## A. 元数据（§1、§2）

- [ ] `name` 与目录名相同；≤ 64 字符，只用小写字母、数字、连字符，不以 `-` 开头或结尾，不含 `--`
- [ ] `description` 非空、≤ 1024 字符；写了做什么 + 什么时候用，关键用途在最前
- [ ] description 没用「我 / 你」；没概述流程步骤；不是包罗万象的能力清单；和相邻技能容易混淆时写了边界
- [ ] frontmatter 是合法 YAML：description 里没有未加引号的半角「冒号加空格」或「空格加 #」，不以 `[`、`{` 开头；没有尖括号
- [ ] 只用开放标准字段和本项目的 `metadata` 键；用了 Claude Code 扩展字段的，正文写明 Codex 侧怎么办
- [ ] 没写 `model`（用户 2026-10-16 定）
- [ ] 用到项目 ai 区固定目录的：`metadata.shelf-scaffold` 与正文「固定目录」一节写的是同一组目录

## B. 授权与确认（§3、§4）

- [ ] 没有 `allowed-tools`；或每一项都是「每次必跑、会弹确认、只读或后果可控」的具体命令
- [ ] 没有裸 `Bash`、`Write`、`Edit`；没有 `Bash(node *)`、`Bash(python3 *)`、`Bash(npx *)` 这类解释器或运行器通配；自带脚本写到了脚本路径
- [ ] 宽授权有用户批准记录（见 §4「已批准的例外」），记录还在
- [ ] 有副作用的动作（提交、推送、发消息、改外部系统、删除）在正文里有确认节点；不可逆或越出授权的动作前先问
- [ ] 触发策略（自动 / 询问后 / 点名时）已登记在协议表或 `ai/JASKILL.md`，不只写在技能正文里

## C. 结构与篇幅（§7）

- [ ] SKILL.md 正文 ≤ 500 行、约 5000 token；最重要的规则在前部
- [ ] 支持文件都从 SKILL.md 直接链接（只下一层），每个链接写明什么时候读
- [ ] 超过 100 行的支持文件开头有目录
- [ ] 同一条信息只在一处；没有用不上的辅助文档（README、更新日志、重复速查）
- [ ] 文件名说明内容；路径用正斜杠
- [ ] 解决过的问题在 SKILL.md 的「经验摘录」有对应的一行（症状 → 结论 → 去哪读）

## D. 正文（§6、§12）

- [ ] 只写模型不知道的，没有常识解释
- [ ] 给默认做法，不是并列的选项菜单
- [ ] 用词前后一致；没有会过期的日期或版本条件（用户决定的日期标注除外）
- [ ] 规则带一句理由；没有叠加的全大写、🔴、「必须」强调；没有事故经过的叙事
- [ ] 贯穿整个任务的规则写成常设指令；必须每次成立的硬规则考虑用钩子
- [ ] 涉及文件修改的：改动按宿主协议的报告规范交代（逐文件给出改了什么）
- [ ] 通用技能：命名没绑定技术域、可变槽位没写死、没有项目数据

## E. 动态特性与两边兼容（§5、§9）

- [ ] SKILL.md 正文没有会被替换的占位符字面量：讲到调用参数、技能目录时换了说法；技能目录占位符只出现在要执行的命令里；读支持文件用相对链接；注入命令里没有 `$0`、`$1` 一类写法（awk 字段也算）
- [ ] 注入命令在当前环境能跑；预期会非零退出的以 `|| true` 收尾；已被权限放行
- [ ] 技能离了注入结果、调用参数也能用；Codex 侧读得懂（不依赖 Claude Code 专有行为，或写了退路）
- [ ] 接收参数的写明了参数用法

## F. 脚本（有脚本时，§8）

- [ ] 不交互；有简短的 `--help`；报错说清错在哪、怎么改
- [ ] 结构化输出到 stdout、诊断到 stderr；输出量可控
- [ ] 破坏性操作有 `--dry-run` 或显式确认参数；退出码区分失败类型
- [ ] 前置条件与依赖写明；不全局安装
- [ ] 判断「被直接执行还是被 import」的，两边都用 `fs.realpathSync` 解析成真实路径再比，并经技能目录的链接路径实际跑过一次

## G. 安全（第三方技能必查，自建技能自检，§10）

- [ ] 读完了目录里的所有文件（SKILL.md、引用的文档、脚本、资源）
- [ ] 没有让模型忽略规则、对用户隐藏动作、遇到特定输入就改变行为的指令
- [ ] 没有硬编码凭据；没有运行时从外部拉取指令或代码；网络访问与声明的用途一致
- [ ] 没有越出技能目录与项目的路径、`../`、过宽的 glob

## H. 测试（§11）

- [ ] 测的是改过的那一份：调用输出开头的 Base directory 指向改动所在的目录（在 worktree 里改时常常不是）
- [ ] 在新会话里跑过：该触发、不该触发（含相近的反例）各 ≥ 3 条真实说法
- [ ] 至少 3 个效果场景，带 / 不带技能对比过
- [ ] Claude Code 与 Codex 各验过关键场景
- [ ] 改了 description、拆分或挪动内容后重跑过上面这些

# 撞额度、停在半路、恢复

> 什么时候读：开工前做准备时；写任务说明的「被打断」一节时；每次被叫醒发现有会话没交回时；额度恢复后。
> 根协议的「长任务与额度」管每个会话自己，本文补的是**主会话怎么照看名下的会话**。

## 1. 开工前

- 查额度（宿主的用量工具）：各窗口用了多少、何时重置，写进台账。**不因额度缩水**（用户 2026-11-24 定）：不换低档模型、不调低 effort、不减步骤、不少派会话；做好撞额度的准备，撞了就停在那里，恢复后从断点接着做。并行几个会话，撞额度就来得快几倍，所以准备要在派之前做完。
- 台账建好：名下会话、各到哪一步、恢复时先拉起什么。任务自己有说明文档的，文档开头那行「进度」写「台账在哪」和当前阶段。
- 按已知的重置时间约一次主会话的唤醒，提示词写「读台账，按恢复顺序接着做；已收尾就什么都不做」。约的时间落在重置之后几分钟；同时只留一个没触发的唤醒，换了就取消旧的。「小任务」默认不约。
- 别只靠宿主叫醒：它只在名下会话**全停了**才叫醒主会话，有一个卡着，别的交回也送不到。几个会话并行时，派活后各挂一条后台命令等交回文件出现（每隔十几秒查一次文件里有没有那一节，有就退出），比轮询会话省得多；后台命令撞额度会丢，另约一次兜底唤醒。
- 用户没说过「额度恢复后自动继续」的，在方案里写一句，让他随方案一起批准。

## 2. 写进每份任务说明的一段

```markdown
- 先建好交回文件（标题和要填的节），边做边写；有进展就提交。被截断时留下的是半份结果，不是零。
- 撞额度或被打断：不用等谁。宿主给了「恢复后自动继续」的就用；能自己约唤醒的约在重置之后几分钟，提示词写「看自己分支的提交和交回文件，从断点接着做」。
- 恢复后先核对：分支、HEAD、没提交的改动、交回文件写到哪；开发服务器、后台任务、浏览器标签要自己重新拉起来；已经落盘的不重做。
- 交回里写一句：被打断几次、各从哪里接上。
```

## 3. 巡查：每次被叫醒先做这一遍

一次列出名下会话（不逐个读对话），和台账对：

| 看到的 | 说明 | 做什么 |
| --- | --- | --- |
| 已结束，交回文件写完、有结论词 | 交回了 | 按 briefs.md 第 7 节处理 |
| 已结束，最后说「等……跑完再交回」 | 挂着自己的后台任务，会被它叫醒（这时列表里也显示空闲） | 不催；等交回文件，到了平常时长的两倍还没有再看 |
| 已结束，没有交回文件或写到一半 | 停在半路：撞额度、出错、或用一段总结结束了一轮 | 先看它分支的提交和交回文件写到哪，再发一条短消息点名还没做的几项，让它接着做 |
| 已结束，最后一条是在问问题 | 等答复 | 能答就答；要用户定的，问用户 |
| 在跑，半小时没有动静 | 等权限确认、等额度、在跑长命令、挂着后台服务、或真卡死 | 限条数看它最后几步再判：等权限的，只能由用户在那个会话里点，把链接给用户、说清点什么；长命令不打断，下次再看；真卡死才停掉那一轮，让它先把已有结果写进交回 |
| 在跑，方向错了 | 消息要等它手上的活做完才读 | 要马上停就停掉那一轮，再发跟进消息 |
| 用户直接和它说过话 | — | 按第 4 节 |
| 列表里找不到 | 被归档、删除或移到顶层 | 看它的分支还在不在；问用户 |

- 结束了一轮不等于做完了。以交回文件、提交和检查结果为准，不以「我做完了」为准。
- 同一个会话自动催两三次还没有进展就停，交给用户：写清它卡在哪、试过什么、有哪几条路。
- 不轮询：派出去之后结束这一轮，等宿主叫醒；台账里写「在等谁」。

## 4. 用户直接和子会话说过话

1. 以对话里的原话为准（怎么查见宿主手法），交回里的转述只当线索；查不到原话的不算用户的要求，问用户。
2. 记进台账当一条新要求：原话、哪个会话、它已经做了什么。用户亲口说的有效，不撤它做的。
3. 看那处改动碰了什么：有没有动「不碰」的文件、共用的件、别的会话的范围；混在别的提交里的让它拆成单独一个，用户不要时好退。
4. 补一条验收（草稿给用户点头），发给测试会话；影响别的会话的一并补消息。没验过的不合。
5. 对用户说一句：看到了、记成哪条要求、影响到哪里、要不要他定什么。不责怪，也不叫他别再去点。

## 5. 额度恢复后的顺序

1. 读台账；核对主会话自己的分支、没提交的改动。
2. 巡查一遍名下会话（第 3 节）。没自己接上的，**一个一个**发「接着做」，先发最挡路的；一起发会马上又撞上。
3. 主会话派出去的子代理：撞额度的会直接失败，不会自己接上。看它留下的部分结果，缺的发消息让它续或重派缺的那块。
4. 把自己被停掉的东西拉起来（开发服务器、后台任务）。
5. 更新台账和进度行，再从断点接着做。

恢复后的这一轮多半是定时唤醒起的自动轮：**能给已有的会话发消息，不能直接开新会话**（见宿主手法）。所以派活要在用户说话的那一轮里一次开齐。

## 6. 自动不了的，如实说

- 周额度：宿主一般不会自动等；约唤醒的时间要跨天，会话得一直开着。写进报告，说清要等到哪天；不自己缩范围。
- app 关了、电脑睡着或合盖：会话内的唤醒不会触发。
- 宿主没有自我唤醒能力（见 Codex 的宿主手法）：写明「额度恢复后请说一声继续」，并把台账写到换谁都能接上。

## 7. 主会话自己的上下文

- 上下文越大，每一步越贵；主会话只留决策、核对、合并和对用户说话。读代码、查资料、看长日志交给子代理，要求回结论加路径，不回原文。
- 交回只读结论节和要核的那几条；看别的会话的对话要限条数，它会把技能正文之类的注入一起倒出来。
- 上下文过半、或每一步明显变贵：在阶段边界把台账写到能接上，再压缩（请用户压缩，或等宿主自动压缩）。压缩后先重读台账和本技能。

# 从艺术需求到可验证实现

## 工具与研究

先检查当前可用技能/工具、现有基准和生产素材；视觉任务优先可用 `codex-visual`，缺失/不可用按实际能力自做。不要硬编码某 CLI 版本、生成耗时、线程可续接、批次能力或价格；需要这些事实时查当前工具说明/官方资料。

位图用图像生成/编辑工具；SVG、组件、shader 和引擎原生形体用对应代码工具；3D 用可用 Blender/生成工具技能。保留生成参考、提示词、种子/设置（仅工具实际提供时）、原文件和采用的派生版本。线程复用是辅助，明确参考图和风格契约才是跨环境依据。

搜索优秀实现时记录“它怎么引导注意/保持趣味/减少负担”，并带同类案例的截图或可打开链接。官方设计指南是检查体验的依据，不能据此强制全项目采用某品牌美学。取用数字标准时注明平台/级别/例外。

## 按需求填写的微观规格

| 类别 | 必须能回答的问题 |
| --- | --- |
| 概念/场景/CG | 情绪、主体与构图、视角/镜头、视觉焦点、前中后景、轮廓与留白、尺寸/安全区、风格参考与禁区 |
| 角色/物件 | 比例、识别特征、姿态、各角度轮廓、材质分区、贴装锚点、遮挡和实际显示尺寸 |
| 光照/材质 | 材质固有色、表面粗糙/微纹理、光源方向/颜色/强度/范围、遮蔽、反射是绘制/近似/实算；与场景和 UI 使用同一环境输入的方式 |
| 粒子 | 轮廓是什么（不能只说“光点”）、大小分布、数量/密度、生成区域/速率、寿命、速度/力场/轨迹、旋转、颜色/alpha/尺度随时间曲线、混合模式、层级、碰撞/遮挡、停止与回收 |
| Shader | 目标画面、坐标空间、uniform/纹理/法线输入、逐步着色公式、可审阅核心代码、参数范围、采样/混合/色彩空间、精度/成本与低配替代；写清哪些是模拟近似 |
| 动画 | 触发→预备→主体→收势/循环，帧率/时长、关键帧姿态或逐帧表、插值函数、锚点/变换顺序、打断/反向/叠加、随机的种子/周期、减少动态效果 |
| 资产交付 | 分辨率/alpha/格式、切片/图集或几何、命名、源文件/导出路径、manifest/使用者、可还原验证 |

不适用项省略；关键审美方向不清楚先聊清楚，再细化技术。需要逐帧确定性时给公式或帧表，明确随机种子与时间采样，不能只列几个形容词。

## 分阶段计划与审核

研究/风格对齐 → 2–3 个有意义的方向 → 推荐方向的微观规格与小样 → 授权范围内制作/实现 → 实景/实际尺寸/关键帧验证 → Monet 视觉审核与设计系统登记。

每阶段写产物和可见验收点，说明依赖。已授权确定的阶段连续推进；有决定性歧义则先做可比较的样板供讨论。修正依据具体失败，不无限更换工具或生图。

透明资产要看实际 alpha 与边缘；纹理要看真实大小、重复接缝和光色；动画要看中间帧/连续播放/中断而非只看静止末帧。性能测量与视觉评估分开报告。无法运行工具时给可审阅结果和明确缺口，不能伪称实测通过。

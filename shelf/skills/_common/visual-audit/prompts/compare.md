# 比稿任务模板（交给 codex-visual）

> 用法：按 codex-visual 技能的流程委派；本模板只规定**任务内容**要写什么。一次只比一个交互点或一块画面。

## 任务说明要包含

1. **对象**：哪个画面 / 交互点（交互点 ID），玩家在这一刻要完成什么。
2. **现状证据**：截图或逐帧胶片路径（附上原图），以及发现 ID 与一句话问题。
3. **约束**（从项目文档摘录原文，不转述）：设计系统里相关的色板 / 材质 / 形状 / 光照条款、动效与反馈规范、
   功能文档里不能动的行为、性能红线（例如运行时不加模糊滤镜）。
4. **方案**：要求给出 2–3 个方向（其中一个是「最小改动」），每个方向说明改了什么、为什么能解决问题；
   需要出图时写清尺寸、透明性、禁止项（图中不许有文字 / 数字 / 水印等，按项目规范）与输出路径。
5. **评判维度**（让 Codex 按维度逐项打分并写理由）：解决问题的程度、贴近现有设计系统、可读性与可达性、
   实现与性能代价、在低动效模式下是否仍成立。
6. **交付**：每个方案的图 / 标注图 + 对比表 + 推荐与理由；产物路径。

## 回来以后

- 独立复核 Codex 的结论（自己看图、对条款），不直接采信；在决策卡里写「采纳 / 部分采纳 / 不采纳」与理由。
- 额度不足或调用失败：按 references/playtest.md §7 记生图需求、用占位继续，决策卡写明「比稿受限」。

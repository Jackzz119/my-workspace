# 专区：界面与体验（ui）

点名 `ui`，或完整一轮开审前读。看的是界面找不找得到、看不看得懂、用得顺不顺。七步的细则在 round.md，这里只写本专区自己的。

## 1. 审什么

- 概念模型、术语一词一义、信息架构、任务流程、状态与失败恢复（设计判断归 UI/UX 技能，本专区负责取证与判定）。
- 信息层级与视觉焦点、单手可达与触控目标、排版随屏幕尺寸的分配、一致性（同一概念同一面孔）、对比度与可读性、空态与长内容、安全区、文案与术语。
- round.md §3 走查来源 W 里除截图与数值外的五个面都在本专区过：命名是否一词一义、入口好不好找、反馈与失败恢复、焦点与键盘、规范与实现的偏差（偏差讲的是风格、动效的，归那个专区）。
- 和别的专区的界线：材质、光影、气质归 `style`；进退场的时长与曲线、能不能打断归 `motion`。「点一下之后，变化出现在哪」两边都看——本专区看起点、落点与遮挡，`motion` 看过程与时长。

## 2. 规则库取哪几节

只跑本专区时按下面取；完整一轮照 rules.md 用法第 1 条挑，下面只当本专区的重点提示。

`rules.md` 的 H、P（P-01–P-14）、V、O；有弹层、面板或会展开的入口加 L；有聊天的加 C；有常驻小组件、播放器的加 W；画面上叠界面的加 G-05、G-10、G-11；K 扫一遍；经验做法看 X-08、X-10–X-12、X-15。

## 3. 各步里做什么

- **采证**：截图矩阵照 round.md §1，状态要拍到容易出问题的那些（空、长文本、错误、未读、部件打开、更窄与更宽的视口）；数值以尺寸（面板占视口的比例、字号、圆角）与对比度为主。
- **调研**：标了每轮的两条照做（research.md §1），加「界面类型专项」。
- **走查**：逐屏按上面的关注面过，每条落到截图或数值；截图里的列宽、留白、截断先查定宽依据再判（round.md §3「先复核再判定」）。
- **比稿**：按 pitch.md §2「界面结构、交互流程、信息布局」那一行派；和 `style` 的题目划清边界（一题比版式、另一题比材质时，另一样照现状画、不计分）。
- **实施**：和材质题都要落地时先版式后材质（round.md §5）。
- **走试玩这条线时**：本专区就是维度 U，按 playtest.md §4 的步骤走，读样式与布局代码、主题 token。

## 4. 验收口径

在 round.md §6 之上加看；完整一轮按本轮范围取，不强制逐条。

- 同一套矩阵重拍并排，尺寸与对比度逐项对照；规则库条目按它自己「怎么检查」一栏量，量不到的写「未测」。
- 用户原话里的量（「不够大」「太小」）拿面积、字号前后比一遍。
- 五个走查面在改后的图与实测里各过一遍：没有新增的一词多义、走不到的入口、没有出口的失败、丢掉的焦点。

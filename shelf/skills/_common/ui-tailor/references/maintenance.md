# UI 常驻文档与验收

每个采用界面至少有：用途/当前状态，实际截图或动态展示，视觉规范，完整操作路径与失败恢复，适用输入方式/尺寸，动效/减动效，实际素材与实现链接。根 UI Markdown 链接这些文档，全局 design-system 再链接 UI 根；不要复制多份“当前总览”。

技术参数沿真实来源维护：Web 可以链接 CSS token，原生应用可以链接主题/资源定义，游戏可以链接引擎样式、材质或预制体。不能以变量仍加载成功推断组件/交互说明仍正确。

| 验证对象 | 最少应看见的证据 |
| --- | --- |
| 视觉 | 真实背景与实际尺寸，亮/暗或项目环境变化，邻近场景/UI 的层级 |
| 交互 | 开启/选择/操作/完成或失败/退出；焦点与草稿符合契约 |
| 输入与适配 | 项目所用键鼠/触屏/手柄，窄屏/缩放/长文，控件目标与状态可辨认 |
| 动效 | 中间帧或实际播放，打断/反向/重复输入、减少动态效果与性能 |
| 数据 | 真实加载、空态、保存与错误；不以假成功掩盖未接入功能 |
| 登记 | 所有采用项有 Markdown 入口、图片/动图/预览和来源，链接能打开 |

新设计按实际平台检索官方无障碍/体验准则，数值须注明条件；不要把一个 Web 尺寸或某个品牌美学当所有游戏/app 的规则。

研究保留有复用价值的来源、候选与选择理由；旧方案把有效结论并入当前规范后再判断保留、概念归档或删除。不能仅因老旧就删掉生产素材或尚被引用的设计。任务过程、回归和普通审核结果默认写在 session；常驻规范仅更新最终设计与必要依据，不新增每轮 report。

迁移时检查引用和依赖，确保 Markdown、图片/动画、预览、代码注释及使用资源的工具路径一起更新。技能目录不参与项目状态或设计决定的维护。

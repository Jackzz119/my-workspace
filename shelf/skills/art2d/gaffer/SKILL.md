# GAFFER — 画里的光，量出来，搬过去

你是 **Gaffer**，片场的灯光师。场景已经画好了，光也画进去了；你的活是**让后加进来的东西站进同一束光里**，
并让场景里的小灯真的在亮。

**触发策略：自动触发** — 往分层画面里加物件、给新物件配各时辰的光、做会亮会闪的小光源、给角色定场景光时直接用。
出图那一步委派给出图工具，按那个工具自己的触发策略来。

回复开头标 `**GAFFER**`。

---

## 原则

1. **光在线性空间里算**：相除、相乘、模糊、混合都先转线性光，最后再回 sRGB
2. **颜色只装物件自己的**：背景从半透明边透进来、出图工具画在边上的环境光，都要去掉；物件和新环境之间的互动（影子、包边光）按目标光生成
3. **比值迁移有前提**：物件和量光的地方受同样的光变化（漫反射、朝向相近）；高光、自己投的影、逆光轮廓要另补
4. **光源是加性层**：开关、闪烁、光晕都是缩放「灯的那一份」，不是把整张图调亮；闪烁克制，只在光源层上
5. **一次换光一个时钟**：底图、布景、活物的光、光源强度都跟着同一个进度走；叠着几层的容器整层淡
6. **每一处露馅都写回技能**：症状 → 原因 → 对策，能做成配置的做成配置（见「不停调优」）

原理、技法、适用条件和来源：`references/knowledge.md`。

## 核心思路：底图之间的比值就是光

同一个地方、同一个机位、不同光的几张底图，逐像素相除，**颜料（反照率）约掉，剩下的就是光的变化**：

```
光比(状态 s) = 底图_s / 底图_参考        （线性光空间，逐通道）
新物件_s     = 新物件_参考 × 光比(状态 s)
```

所以新物件**只在一种光（参考状态）里画一次**，就在那张底图上画、和周围一起受光；其余每种光由脚本算。
不需要去光的「中性母版」，不需要法线图，也不为每种光重画。

- 比值在**线性光**里算，在**对数空间**里做归一化卷积（模糊）：单像素的比值有噪声，平滑后才是光
- **只用受光面**：玻璃（窗外景色会变）、自己发光的东西（灯罩、屏幕）的变化不是光，排除掉；排除区里的光由周围扩散补上
- **发光的部分不重打光**：灯笼的烛火、玻璃里的亮，按原样保留

这套办法的可信度可以直接测：拿一件**每张底图里本来就有的东西**（一把椅子），只从参考图重打光到其余各张，
和它本来画的样子比（`light.py check`）。误差应明显小于「不打光直接搬过去」。

## 三类东西，三种吃光的方式

| 类别 | 例子 | 怎么吃光 | 交付 |
|---|---|---|---|
| **布景**（不动的物件） | 窗边座、转过去的椅子、倒扣的书 | 每种光一张图：参考图 × 光比，发光部分保留 | 每个状态一张透明小图 + 一个框 |
| **光源** | 灯笼、烛火、串灯 | 画里画亮的样子（属于布景）+ 运行时一层加亮光晕，强度随时辰变，轻微闪烁 | 位置、半径、颜色、各时辰强度、闪烁幅度 |
| **活物**（会动的） | 角色、猫 | 运行时乘一个 tint：在它待的位置上量出的光比（每种光一个值）；挨着光源时再往光源色混一点 | 每种光一个 tint 值 |

活物的方向光、轮廓光与影子的做法（挨着灯的角色）写在 marionette 的 `references/runtime.md`「受光」与 `references/shading.md`，本技能管它用的场景光从哪来，
以及它挡掉的那份光（坐在被窗照亮的毯子上：`light.py shade`，见 `references/runtime.md`「活物的场景光」）。

## 流水线

```
1 出图    在参考状态的底图上画新物件（只改物件那一块），每件交一张整图
2 切图    和它画在上面的那张图逐像素比差，得到透明度；半透明的边去掉背景色；投在背景上的影子随差值一起留下；
          玻璃前的边另有做法（references/edges.md）
3 重打光  每个状态：线性光 × 光比；发光区保留原色
4 量光    活物的位置：每个状态一个 tint
5 自测    check：用一件本来就有的东西验证光比；preview：所有物件叠回每张底图看接缝与颜色
6 接入    运行时按状态挂图层、随底图一起淡入淡出；光源一层加亮光晕 + 闪烁；活物乘 tint
```

脚本：`python ${CLAUDE_SKILL_DIR}/scripts/light.py all --config <场景配置.json> --review <目录>`（`check` / `tint` / `shade` 单独跑）。
依赖：Python 3.10+、`numpy`、`Pillow`。配置写在项目里（底图路径、参考状态、排除区、物件的区域与阈值），
格式与每个参数见 `references/method.md`「配置」。

## 出图要求（交给出图工具的 brief 里必须写）

- 在**参考状态那张整图**上画，输出同尺寸、逐像素对齐；物件以外尽量不动（切图靠比差，周围漂移会变成光圈）
- 物件**带着那张图的光**画：受同样的台灯、窗光，有接触阴影；不加光晕、描边
- 物件要分开出：每件一张，或者「每张只比上一张多一件」，这样每件都有干净的比差背景
- 背后被挡住的东西（物件后面的墙）以后要露出来的，先单独出一张「挡住的东西拿走」的图

## 运行时（引擎无关）

- **布景**：每个状态一份，和那个状态的底图同组；换时辰 / 开关灯时跟着底图一起交叉淡化，不单独算光；
  叠着开灯 / 关灯两版的组要**整层淡**，不然下面那版会在中途透出来
- **活物的光跟底图同一个时钟**：换时辰时从当前值插到新值，时长和底图淡化一样
- **出现和消失是交叉淡化**：布景的变化（椅子转过去、书放下）是「换了一个样子」，不是动作，用透明度渐出渐进
- **光源**：一层加法混合的径向光晕（中心暖、边缘透明），盖在它照到的布景上、挡在它前面的东西下面；
  强度 = 各时辰强度 ×（1 + 闪烁），闪烁是几条不成整数倍的正弦相加再加偶尔的小暗跳，幅度 5–10%，低动效时不闪
- **活物**：tint 在开灯 / 关灯两个值之间按灯的亮度插值；挨着光源再向光源色混（混多少看距离和光源强度）

细节与参考数值：`references/runtime.md`。

## 经验摘录（常见坑）

一条一个遇到过的情形：认出它的症状 → 结论 → 细节在哪读。碰到相似的情形先在这里找，再去读那一节。

- **在 sRGB 里直接除**：暗部比值失真、颜色发灰。先转线性光
- **比值不平滑**：笔触、纸纹、两张图之间的微小漂移都会变成物件上的花斑。σ 取 20–30 px（1500 px 宽的图）
- **把玻璃和灯罩算进去**：窗外的城市、灯罩本身的亮变化会被当成光，物件跟着乱闪。排除它们
- **切图阈值太低**：出图工具的整体漂移（色差 4–7）被当成物件，边上一圈光晕。阈值下沿高于漂移，再用实心区补洞
- **边上有色圈、挂着一条背景、物件后面是窗玻璃**：切边的问题，查法与对策（实心区、玻璃前的读边 / 描边、前景色估计、去溢色）
  都在 `references/edges.md`。先把物件叠到纯品红上看外圈，再动手
- **换光时闪一下 / 先亮再灭**：多半不是图的问题，是图层各淡各的或叠着的两版被分别淡化，见 `references/runtime.md`「整层淡化」「一个时钟」
- **换光淡完的最后一帧，抠出来的物件边缘跳一下**（看着像「离屏图消失时闪了一下」）：每种光一份的物件（椅子）是新的盖在旧的上面淡入、
  淡完才撤旧的，软边两份叠厚，撤的那一帧变薄。轮流占同一个位置的透明物件要**混**：旧的同时淡出、两份按透明度加法混进父层的离屏图，
  见 `references/runtime.md`「整层淡化」。逐帧比相邻两帧，淡完那一帧的变化不该突然变大、也不该集中在轮廓上
- **玻璃区的下沿停在真实玻璃上面**：玻璃区以下改用比差，下沿和真实玻璃底之间那条窗会被当成物件留下（猫屁股下、椅背下沿一条蓝），
  或者描边没盖到的那一截物件被切掉（横档上一道裂缝）。玻璃区是矩形 `[x, y, w, h]`（第四个数是高，不是下沿），
  下沿要盖到窗玻璃真实的最低处，描边要盖到物件在这一段的真实下沿，见 `references/edges.md`「玻璃前」
- **毛这类软边立在窗前，怎么切都像贴纸**（边发虚、飞出去的毛尖被削平、压在东西上的那截少一块）：从底图里切总差一口气
  （比差留一条窗、读色把亮灯读成毛、手描轮廓削平毛尖）。让出图工具在原场景里**重画它，物件以外全涂纯绿**，按颜色抠（色键）：
  毛尖一根根留下、没有绿圈。它坐着、靠着的东西也要涂绿；挨着它的杂物只在那一小块里按颜色去掉。
  见 `references/edges.md`「软边对着窗：绿幕重画」
- **重画的物件放回去，看着浮起来或大了一圈**：按旧图对位：最宽处同宽，身子底边落回旧图的底边。旧图的底边按透明度过半量，
  按几乎不透明量会高出几 px（坐着的猫就浮在毯子上）。见 `references/edges.md`「软边对着窗：绿幕重画」最后一条
- **tint 不能提亮**：tint 是乘法，最大是 1。参考状态不是最亮的那种光时，最亮那几种会被截到 1；
  `tint` 会给出增益（可以大于 1），活物用颜色矩阵乘增益，或者按最亮的光出图
- **白色的活物被底图的颜色染透**（夜里发黄、关灯发蓝、黄昏发光）：量出的增益直接乘在单独画的浅色主体上。
  先压色度、收高光、再乘这张画自己的曝光，见 `references/runtime.md`「活物的场景光」
- **光源光晕盖在挡它的东西上**：光晕图层要放在光源和它前面的物件之间，不然灯光会「透」过前面的椅子

## 自检清单

- [ ] `check` 的误差明显小于不打光（每个状态都看）；明显没改善的状态，在报告里说原因（逆光、画法不同）
- [ ] `preview` 看过每个状态：物件边缘没有光圈、颜色和周围一样、影子还在；玻璃前的物件叠到品红上看过外圈
- [ ] 发光区没被压暗（关灯、夜晚时灯笼还是亮的）
- [ ] 活物的 tint 每个状态都有；最亮的几种被截到 1 的有说明
- [ ] 运行时：换时辰、开关灯，布景跟着底图一起变，没有先后一拍；低动效下光源不闪
- [ ] 每个状态放大看玻璃前的物件边（最容易露馅）；换时辰、开关灯时逐帧录一遍（浏览器的逐帧截屏），
      量几块区域（灯罩、物件、活物）的平均色：应单调地从一端走到另一端，不冲过两端、不在第一帧或最后一帧跳

## 不停调优

这个技能靠每一轮用下来的问题长大：哪里露了馅、用什么办法补上，当轮就写回来，不留在会话里。

- 新的毛病写进「常见坑」或对应的参考文件：症状（用户看到什么）→ 原因 → 配置或脚本里的对策；能做成配置选项的做成选项
  （`glass`、`glass_edge: trace` 都是这样来的）
- 学到的新技法、新来源进 `references/knowledge.md` 对应小节，标明适用条件和来源
- 自测的数字留着：同一件物件改了算法或参数，重跑 `check`，误差只许降不许升
- 项目里的配置（底图、排除区、每件的区域与实心区）归项目，技能只写方法；项目登记里写清配置在哪

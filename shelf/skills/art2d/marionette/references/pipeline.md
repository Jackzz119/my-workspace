# 流水线详细规范

> 按需加载。跑 `scripts/rig.py`、写 `rig.json`、调阈值、查文件格式时读。

## 目录约定

`rig.json` 里的三个目录由项目决定（登记在项目文档里）：

```
<source>/            原始生成 PNG + 生成报告与 prompt 记录（入库：这是唯一的原稿）
<build>/             中间产物（不出货；可 gitignore，随时能从 source 重建）
  check.json … export 各步的记录
  raw/               assemble：同一并集框裁好的原图，像素未动
  final/             align 之后：对齐的闭眼帧、形变场、权重图——export 只读这里
  review/            每一步的证据图
<runtime>/           出货：*-open/closed.webp、idle-*.png、morph-*.png、rig.json
```

每一步**只拥有自己的产物**，每次都从上一步的产物重新推导：`assemble` 清空 `raw/`，`align` 清空 `final/`，
`morph` / `weights` 只重写自己那类文件，`export` 只删自己那几类过期文件。所以重跑任何一步都安全，
不存在「重跑装配后忘了再对齐」这种顺序陷阱。

## rig.json 字段

坐标一律是 **source 画布**的像素（生成出来的那张图的尺寸），脚本内部自己换算到裁边后的画布。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `anchor` | 必填 | 基准姿势 id，其余姿势都拿它比 |
| `poses` | 必填 | `id → { blink, morph, slow, probe, align_to, free, accept }`：`blink` 有闭眼帧；`morph: false` 不参与形变（动作跨度太大的）；`slow` 进出用慢速淡入淡出；`probe: false` 不量肩线（头发 / 手臂会挡住测量列的姿势，如趴睡）；`align_to` / `free` 见 align；`accept: "原因"` 把这个姿势 check 的 FAIL 降为 WARN 并每次打印原因——只用于已经拍板接受的已知缺陷，不用于新问题 |
| `poses.<id>.chain` | `false` | 关键帧链上的中间帧：只和 `sequences` 里的邻居算形变场，不参与全员两两配对 |
| `poses.<id>.hides` | `[]` | 这一帧里被它顶替的场景部件（杯子在手里了）：导出进清单，运行时那个部件按这一帧的显示程度渐隐 |
| `poses.<id>.holds` | `[]` | 这一帧**画在手里**的场景部件（要在 `parts` 里）：align 量出它离原位的位移，导出进清单；运行时在进出这一帧的那一步让场景的部件沿位移跟着手走、到位才消失。握住还没拿起的帧只标 `holds`（场景那只继续盖在上面），拿起那一帧标 `hides` + `holds`，之后的帧只标 `hides` |
| `poses.<id>.free` | `"face"` | `align_to` 时可以不同的区域：`"face"` / `"eyes"` / 一个框 / 它们组成的列表（链上的帧用 `["face", 手臂那一片的框]`，头发仍对齐回 anchor） |
| `sequences` | `{}` | `名字 → { frames, step_ms, hold_ms, back, swap }`：关键帧链。`frames[0]` 是待机姿势；`back: true` 停 `hold_ms` 后倒着走回来（反应），不写是进入某个状态的链（入睡），离开时倒着走。`swap` 是每步换图的窗口，默认 `step`（快，网格带着动作走）；某一步要「长出」光流推不出来的东西、而周围几乎不动时（头不动、嘴张开）写 `"wide"`，不然那一步会在几十毫秒里跳出来 |
| `placement` | `null` | `{ "offset": [x, y], "scale": s }`：已知的座位（source 画布 → 场景），第二个人物坐同一张椅子时用，代替 `plate` 配准 |
| `parts` | `{}` | `名字 → 图片路径`：场景部件在**场景坐标**里的 RGBA 图（整张场景图大小、只有这个部件，如桌上的杯子），`holds` 拿它找手里画的是不是同一件、在哪。要求 `plate` 或 `placement` |
| `source` / `build` / `runtime` | 必填 | 见上 |
| `source_pattern` | `{pose}-{eye}.png` | 原图命名，`eye` 是 `open` / `closed` |
| `source_single` | `{pose}.png` | 没有闭眼帧的姿势可以只有这一张 |
| `url_base` | `""` | 运行时取文件的 URL 前缀，写进清单 |
| `grid` | `24` | 网格顶点间距（画布 px）。越小越细、越费；24 对 1000–1500px 的半身像足够 |
| `canvas.size` | anchor 的尺寸 | 每张原图都必须是这个尺寸 |
| `canvas.probes_x` | `[]` | 量肩线的列：每列取第一个不透明像素的 y，和 anchor 比。选肩膀 / 上臂外轮廓经过、头发和手不会经过的列 |
| `poses.<id>.probes_x` | 用 canvas 的 | 这个姿势自己的肩线测量列。伸手拿东西的帧那一侧的肩膀本来就会抬（第一个案例：够杯子的那侧抬 5–15px，拿书那侧 0±2px），只量不动的那一侧 |
| `canvas.cut_y` | `null` | 躯干截断线（坐在桌后的人物）。`null` = 不量 |
| `canvas.cut_probe_x` | `[]` | 量截断线的列：在 `cut_y ± 40` 内找「实 → 空」的边；找不到干净边的列记为不可观测 |
| `poses.<id>.cut_probe_x` | 用 canvas 的 | 这个姿势自己的测量列。**只量躯干本身露出来的列**：书、本子、手搭在那一列时，它们的下沿会被当成「躯干伸到了桌面下」，所以中间被道具挡住的姿势填 `[]`，只给躯干露着的姿势（捧杯喝水）填列。第一个案例吃过亏：窗口只有 ±40 时，喝一口的躯干下沿在 944，落在窗口外被当成「挡住了」而放行 |
| `canvas.cut_window` | `80` | 截断线在 `cut_y ±` 这个范围内找 |
| `canvas.cut_plate_y` | `null` | 桌面远沿在**场景图**上的 y（人工在底图上量）。assemble 用配准把它换算到画布上，和 `cut_y` 差超过 `cut_fail_px` 就 FAIL 并给出正确值。**有场景图时必填**：截断线是场景决定的，不是 brief 里拍脑袋写的数 |
| `poses.<id>.fit_cut` | `false` | 截断线偏离 `cut_y` 超过 `cut_fail_px`、但在 `fit_cut_max_px` 以内的姿势：check 降为 WARN，align 把截断线上方约 150px 的一带竖向拉伸到 `cut_y`（睁眼、闭眼用同一张映射）；超出 `fit_cut_max_px` 仍 FAIL、要重出。只给生成方把截断线画偏了几像素的姿势用 |
| `canvas.crop` | `null` | `[x0,y0,x1,y1]`：固定共享画布。**运行时开始用画布坐标（触碰区、锚点）之后就要固定**：不固定时画布是所有帧的并集框，换一张图就可能变，运行时的坐标会整体错位；固定后有帧超出就停下报错，绝不裁掉 |
| `face.boxes` | `{}` | `姿势 → [x0,y0,x1,y1]`，覆盖自动找脸。自动找脸按「上部最大一块暖色皮肤」，只适合暖色皮肤的人类；动物、机器人、偏冷或风格化肤色一律手填 |
| `eyes.boxes` | `{}` | `姿势 → 框`，覆盖由脸框推出的眼带（脸框上 12%–55%，左右各外扩 10px） |
| `hair.mode` | `dark` | `dark`（亮度 < `lum_max`）/ `light`（亮度 > `lum_min`）/ `color`（与 `rgb` 各通道差 < `tol`）/ `mask`（用 `hair.masks`）/ `none` |
| `hair.masks` | `{}` | `姿势 → 遮罩 PNG`（source 画布尺寸，白 = 头发）。遮罩永远优先于自动识别 |
| `hair.by_pose` | `{}` | `姿势 → {上面任意字段}`，单个姿势覆盖（头枕在深色袖子上时 `{"mode": "none"}`） |
| `hold.skin_below_chin` / `hold.bright_low_sat` | `true` | 下巴以下的皮肤（手）、下巴以下的亮而不饱和的像素（纸、书）不随呼吸动 |
| `hold.masks` | `{}` | 额外的「不许动」遮罩（杯子、键盘……） |
| `breath.anchor_y` | `cut_y + 60`，否则画布底 | 呼吸权重为 0 的那条线；从它到肩线（下巴 + 0.35 脸高）渐变到 1 |
| `breath.masks` | `{}` | `姿势 → 灰度 PNG`，直接给呼吸权重 |
| `plate` | `null` | `{ "path": 场景图 }`：把 anchor 配准到这张场景图上，结果写进清单的 `placement` |
| `regions` | `{}` | `区域名 → { 姿势 → [x0,y0,x1,y1] 或 "auto" }`：引导形变用的对应区域（见 morph）。`"auto"` 用由脸框自动得出的头部框；两个姿势都写了同一个区域才会引导 |
| `thresholds` | 见下 |  |

## 阈值与它们的来历

第一个生产案例（桌后半身人物、7 个姿势、1536×1024 画布）实测校准，换项目时先按这些跑，看证据图再调：

| 阈值 | 默认 | 含义 | 实测 |
| --- | --- | --- | --- |
| `probe_warn_px` / `probe_fail_px` | 3 / 8 | 肩线相对 anchor 的最大漂移 | 合格姿势 0–4px；一个 9px 的姿势在交叉淡化时肩上出现双线 |
| `cut_fail_px` | 8 | 躯干截断线偏离 `cut_y` | 偏 16–17px 的姿势在桌沿留下一道硬边 |
| `fit_cut_max_px` | 16 | 标了 `fit_cut` 的姿势，截断线偏差在这以内由 align 拉伸修正 |  |
| `blink_reject` / `blink_solid_max` | 0.15 / 0.01 | 原始闭眼帧：眼带外颜色变化 > 24/255 的像素占比 / 其中 5px 以上成块的占比 | 成块占比才分得出好坏：合格帧 0–0.4%（整体 2–8%，多是沿轮廓的漂移，对齐修得回）；书下那截 T 恤没了的帧 2.2–3.4%（整体反而只有 5.6–8.7%）；重画了袖子的那张整体约 9% |
| `blink_after_max` / `blink_solid_after_max` | 0.02 / 0.001 | 对齐后同一指标 / 其中成块的占比：成块 ≤ 0.1% 时上限放宽到 2 倍 | 对齐后 0.8–1.7%；一张 2.4% 的全是发梢、针织、发夹上的零散细点（成块 0.02%，发夹轮廓中心偏 1.3px），眨眼 140ms 里看不出 |
| `morph_err` | 0.12 | 形变后与目标的平均颜色误差（0–1），比的是看得见的颜色：每个像素先按 alpha 合成到中灰，透明处两边都是灰、不计误差（透明像素底下存的颜色不算） | 合格 0.01–0.06；单靠它分不出坏对（坏对 0.07–0.11） |
| `morph_sil` | 0.05 | 形变后与目标轮廓对不上的占比 | **合格 ≤ 0.027，坏对 ≥ 0.068**：真正起区分作用的是这个 |
| `alpha_empty` | 8 | 裁边时 alpha 低于它算空 |  |
| `hold_search_px` | 200 | 手里的部件在离原位多远以内找 | 要求抬 70px 的拿起帧实际抬了 130–157px |
| `hold_match_min` / `hold_rms_max` | 0.5 / 0.14 | 找到处与场景部件的边缘相关 / 颜色 RMS（0–1） | 照版式图原位重画的握杯帧 0.69–0.75 / 0.11–0.12，竖直拿起帧 0.60–0.64 / 0.125；从零画的杯子位置对、样子不同 0.46 / 0.15（交接会跳）；没画杯子的帧 ≤ 0.30 |
| `hold_rest_px` | 10 | 只 `holds` 不 `hides` 的帧里部件离原位最多多远 | 场景那只会被挪过去盖住它；原位重画的握杯帧 0–1px |
| `rigid_min_matches` / `rigid_missed_px` | 6 / 20 | 光流漏掉的刚体块：至少这么多对互相一致的特征匹配，每对离光流给的位置超过这么多 px | 杯子真实移动 194px，光流只给出 45px；11 对匹配、相似变换位移 (−96, −151)、缩放 1.03 |

眼外变化这个指标用预乘 alpha 后的颜色、阈值 24/255，所以它量的是「看得出的变化」，不是重采样噪声。
生成方的自审报告常用更敏感的阈值（如 8/255），数字会大很多，两边不要直接比。

## 各步做什么

### check

逐张：尺寸对不对；透明是不是真的（完全透明的像素 < 5% = 画出来的背景，FAIL）；主体平均 alpha
（< 245 = 人物半透明，场景会透过来，WARN）；肩线漂移；截断线。逐对闭眼帧：眼带外变化，超 `blink_reject`
就标记拒绝（这个姿势出货时不眨眼，不算整套 FAIL）。

### assemble

所有帧取 alpha 并集框（外扩 2px）统一裁——**不能每张单独裁**，那样会破坏姿势之间的对齐。
配准：SIFT 特征（两边先做 CLAHE，让均匀光的人物和有氛围光的场景按形状而不是按光匹配），
RANSAC 求相似变换，再按「只有缩放 + 平移」重解平移（2D 运行时放精灵就用这个模型）。
裁边移动了画布原点，要折算进 `origin`。旋转 > 1° 或残差中位数 > 3px 说明配准松了，先看 `register.png`。

### align

`flow(open, closed)`（DIS 光流，MEDIUM 预设，灰度 + 中性灰背景合成，让轮廓也参与匹配）→ σ=3 高斯平滑 →
眼带内换成周围的整体运动（归一化卷积，σ=40，边缘 8px 羽化）→ 沿它采样闭眼帧。
为什么眼带要特殊处理：睁眼和闭眼在眼睛那里是**不同的东西**（虹膜 vs 眼睑），光流会把眼睑硬拉到虹膜边缘，
睫毛线被拉成 S 形。

**反应对齐**（`poses.<id>.align_to = 目标姿势`，`free` 默认 `"face"`，也可 `"eyes"` 或一个框）：同样的做法，
把反应姿势的睁眼帧对齐到目标姿势的几何上，只有 `free` 区域（整张脸：笑会张开下巴、脸红到脸颊）可以不同。
用在「头和身体本不该动」的反应上（笑、脸红、眨一只眼），**不能**用在本来就要动的反应上（抬头迎向摸头的手）。
它先于眨眼对齐执行；这个姿势若有闭眼帧，闭眼帧先对齐到自己的睁眼帧，再沿同一个修正场移动。
能修的是**几何漂移**（发型轮廓整体胖了一圈、肩线偏了）；修不了的是**画出来的多余内容**（多画了一缕头发）——
`align-<姿势>.jpg` 上对齐后仍成块的红色就是这种，只能重出。第一个案例：轮廓差 0.46% → 0.21%，
右侧发缘的细条基本消失，剩下一缕多画的头发。

**手里的部件**（`poses.<id>.holds`）：不移动任何帧，只测量。`parts` 里的部件图经座位变换搬到画布上（画布四周各留
`hold_search_px`，部件可以有一截在画布外——桌上杯子的底常在画布下沿之外），在这一帧里 ±`hold_search_px` 内找它：
比的是**边缘**（部件遮罩内梯度幅值的归一化相关），不是颜色——灰杯子和灰袖子颜色一样，边缘不一样；还要求这一帧在那里
露出部件的 60% 以上。找到的位置再量颜色 RMS，两个数任一不过就 WARN（手里画的不是场景里那只，交接时会跳），
只 `holds` 不 `hides` 的帧再查位移不超过 `hold_rest_px`。位移写进 `align.json` 的 `holds`，export 带进清单。

### morph

每对姿势（无序对）算双向光流，σ = `grid × 0.6` 平滑（形变场只需要大尺度的形状移动，不需要发丝级细节），
两个方向都检查 err 和 sil，**两个方向都过才出货**（运行时同时要用 a→b 和 b→a）。
离线模拟：按运行时同样的时序（见 `runtime.md`）合成 t=0/.25/.5/.75/1 五帧，所以不用进运行时就能看到过渡效果。
第一个案例里，模拟图和浏览器实拍在同一帧出现了同样的问题（被拖扁的书），这一步的预判是可信的。

**光流漏掉的刚体块**：身体前面移动 100px 以上的小物件（端到胸前的杯子），DIS 光流跟不上，轮廓又看不出来（它在身体轮廓里面移动），
结果是换图时两只杯子。所以每一对还做一遍特征匹配（SIFT、双向、比率检验）：一簇互相一致、离光流给的位置超过 `rigid_missed_px` 的匹配，
能用一个相似变换解释（缩放 0.85–1.18、转角 < 25°）的，就在它的框里（外扩 45%、羽化）整体按这个变换搬移，两个方向互为逆变换，
框外仍用光流；只在框内颜色误差确实下降时才采用，记录里是 `rigid`。框里混进了会弯的手臂时误差会上升，这一块就不用——
这类步真正的修法是再插帧。

**被场景部件盖住的地方不算**：一对姿势里有一张 `holds` 了场景部件、这一步部件画在人物前面（没被 `hides`，或正被搬运），
部件沿 holds 位移经过的地方从 err 和 sil 里扣掉（记录里的 `covered_px`）。第一个案例：握杯那一帧原位画了杯子（占轮廓约 4.4%），
伸手 → 握杯本来差 5.7% 过不了，扣掉被桌上那只盖住的部分后 2.3%。

**关键帧链的邻居**：`sequences` 里每一对相邻帧**一定**算光流（不管 `morph` 标没标），链只和它最差的一步一样顺；普通姿势之间照旧两两配对，链上的帧（`chain: true`）不参与。

**引导形变**：一块**刚体**走得太远、光流跟不上（头从快睡着落到手臂上），光流对不上就只能盖上再淡出，旧姿势那颗头
会在空中淡出，成了残影。只要知道「这一块去了哪儿」，就能在那一块里直接造形变场：同名区域在两个姿势里各有一个框，
框到框做缩放 + 平移、向外羽化（羽化宽度 = 框短边的 1/3），**框外仍用实测的光流**。区域在 `regions` 里按姿势写，
`"auto"` 表示用由脸框得出的头部框（向上长到头顶、两侧包住头发）。触发条件：这对姿势**都写了同一个区域**且光流没过。
第一个案例里「手从书移到杯子」用引导形变做过一次，效果是一个变形的人举着杯子从下面长上来，被用户否了；
手、道具这类大动作一律改用关键帧链，引导只留给刚体的一小段。
**没有指标能判断引导形变好不好，必须看模拟图**（记录里的 `guided_sil` 只作参考）。export 把这些对写进清单的 `guided`，运行时让它们和慢速姿势一样在窄窗口（35%–65%）换图（`morphSwap`）；换引擎时适配层要把 `guided` 传给切换器。
第一个案例：快睡着 → 趴下这一步光流差 5.2%（门槛 5%），盖上再淡出时有两颗头；引导后头是一整颗落下，中段手臂和下巴还有
约 270ms 的叠影——这一步真正的修法是再插一帧，引导只是兜底。

### weights

每个姿势一张网格尺寸的 RGB PNG：R 呼吸、G 头发。几个关键处理：

- **先模糊、后乘「不许动」**：反过来的话胸口的运动会晕染到书上，书跟着呼吸；
- 头发只认「脸周围一圈、下巴以上、脸椭圆以外、并且和头顶那块连通」的像素——衣服常和头发一样深，只靠颜色会把帽兜认成头发；
- 发根权重 0.25、发梢 1，按离脸中心的距离渐变，所以发梢飘、发根不动；
- 呼吸从 `breath.anchor_y` 的 0 渐变到肩线的 1，不整体缩放人物（整体缩放 = 人变胖变瘦）。

### export

帧：WebP，quality 90、alpha 无损。数据图：原样复制 PNG（它们是数字，不能有损压缩）。
清单 `rig.json` 只列真正出货的东西，运行时据此决定谁眨眼、哪些对能形变。
有 `shade` 时每一帧先加深毛缝再编码（`scripts/shade.py`，`references/shading.md`）。清单里每个文件名带内容哈希（`?v=`）：
同名文件换了内容，CDN 和浏览器也会重新拿；运行时取清单本身要绕过缓存（`fetch(url, { cache: "no-cache" })`）。

## 文件格式

**idle-<姿势>.png**：`cols × rows` RGB，`cols = floor(w/grid)+1`，`rows = floor(h/grid)+1`。
像素 (i, j) 对应顶点 `(linspace(0, w-1, cols)[i], linspace(0, h-1, rows)[j])`。R = 呼吸 × 255，G = 头发 × 255。

**morph-<a>-<b>.png**（`flowFormat: "rgb12"`）：同尺寸 RGB。每个顶点的 dx、dy 各 12 位：
`v = round(d × 8) + 2048`（范围 ±256px，精度 1/8px），
`R = dx >> 4`，`G = (dx & 15) << 4 | dy >> 8`，`B = dy & 255`。alpha 恒 255，避免浏览器预乘改动数值。
含义：a 的顶点 p 上的内容，在 b 里位于 `p + d`。
（为什么不用「R = dx + 128」：那只能表示 ±127px，手臂一类的大动作会被截断。）

**rig.json（运行时清单）**：

```json
{
    "version": 2,
    "canvas": { "w": 1377, "h": 1015 },
    "grid": 24,
    "flowFormat": "rgb12",
    "anchor": "reading",
    "poses": {
        "reading": {
            "slow": false,
            "open": "/x/reading-open.webp",
            "closed": "/x/reading-closed.webp",
            "idle": "/x/idle-reading.png"
        },
        "asleep": { "slow": true, "open": "/x/asleep-open.webp", "idle": "/x/idle-asleep.png" },
        "sip-4": { "slow": false, "hides": ["mug"], "holds": { "mug": [0, -132] }, "open": "/x/sip-4-open.webp" }
    },
    "morphs": { "reading-glance": "/x/morph-reading-glance.png", "glance-reading": "/x/morph-glance-reading.png" },
    "guided": [],
    "sequences": { "doze": { "frames": ["reading", "doze-1", "doze-2", "asleep"], "stepMs": 750 } },
    "placement": { "origin": [346.02, 92.83], "scale": 0.57417 }
}
```

`placement` 只在配准过场景图时出现：画布左上角落在场景图的 `origin`，按 `scale` 缩放。
`holds` 的位移是画布 px，运行时乘上画布的缩放再加到部件的原位上。

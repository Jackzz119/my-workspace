# 生成：怎么出一套能动起来的姿势图

> 按需加载。写生成 brief、出图、判断要不要重出时读。brief 模板：`../templates/brief.md`。

## 目标不是「好看的图」，是「一套互相对得上的图」

运行时会把这些图原地叠在一起切换、变形。任何一张的身体、脸、比例漂了，都会在切换时变成跳动、双线或多出来的一块。
所以验收标准的第一条是**一致**，其次才是好看。

## 出图顺序

1. **anchor**：最常出现的状态姿势（通常是默认在场状态），按画布规格从人物设定 / 已定稿的场景图重画一张。
   单独验收：身份对、构图对（头顶位置、截断线、居中）、真透明、主体不透明、边缘干净。**anchor 不过，后面都不出。**
2. **其余姿势**：每一张都是「以 anchor 为输入的编辑」，不是新画。prompt 里写清只改哪些部位。
3. **闭眼帧**：以对应的睁眼帧为输入，只改眼睑。
4. **不参与形变的大动作**（趴下睡觉等）：同样从 anchor 编辑，但允许肩线变化；在 `rig.json` 里标 `probe: false`、`morph: false`。

## 第二个人物坐同一张椅子

anchor 的 brief 带三类参照：第一个人物的 anchor（座位、比例、桌沿 y）、她自己的设定图（身份）、「她坐在这张桌子前」的概念图（体量和光）。生成方常把头顶位置、肩宽当硬指标卡死，但这两项是「她看起来多大」，应该合成到场景里和第一个人并排看——第一个案例里 6 张全被生成方判不合格，合成后有 4 张都自然，挑了体量最像「比他小一号」的那张。

## 先量场景，再写数字

brief 里的每个位置数字都要从场景量出来，不能估：尤其是**躯干截断线**——它必须正好落在场景里桌面（或别的遮挡物）的远沿上。做法：在底图上量桌面远沿的 y，用 anchor 的配准（assemble 的 `registration`）换算成画布 y，写进 `rig.json` 的 `cut_plate_y` / `cut_y` 和 brief。第一个案例里 brief 写了「截断线 y=900」，实际桌沿在画布 y=968；手和书挡着的姿势看不出来，双手捧杯的姿势一出就在躯干和桌面之间露出一条椅背。新人物的第一张 anchor 出来、配准之后，先做这一步，再出其余姿势。

## 每张 prompt 都要重复的不变量

模型不记得上一张，所以每张都要把不变量写全（模板里是一整段，原样复制）：

- 画布尺寸精确一致，横 / 竖版一致；**真透明背景**（alpha = 0，不是画出来的棋盘格、不是纯色底）；
- 人物水平居中，头顶离上边的距离；肩膀外轮廓的大致 x 范围；
- **躯干截断线**：坐在桌后的人物，截断线以下不画躯干（被桌面挡住），前臂、手、手里的东西可以搭到桌面上、超出这条线；
- 肩、胸、截断线在每个姿势里位置和比例不变，**只有头、手臂、手、表情、道具变**；
- 光：均匀、略暖的正面光，柔和体积，**不要强轮廓光、不要投影到人物外面**（场景光由运行时统一染色）；
- 只画这一个人：没有桌子、椅子、背景、其他人、文字、边框。

## 闭眼帧

- prompt 写「只改两只眼睛为轻闭的眼睑；眼镜框、眉毛、嘴、脸型、头发、头部角度、肩膀、手、道具**全部不变**」；
- 生成模型做不到逐像素不变，几何会漂一两个像素——这由流水线的 align 步骤对齐回来，**不要为了这点漂移反复重出**；
- 但**纹理重画了**（袖子、衣褶、发丝走向变了）对齐救不回：check 按眼外 5px 以上成块的变化拒掉（> 1%；整体变化 > 15% 也拒，见 `pipeline.md` 阈值表），那张要重出；
- 重出时给模型两张输入：anchor（锁身体）+ 对应睁眼帧（锁表情），并在 prompt 里点名上一版改坏了哪里。

## 反应姿势怎么设计才好变形

光流形变能补出「同一样东西移动了」的中间帧，补不出「一样东西消失、另一样出现」。所以：

- **小幅、局部的变化最好**：抬眼、闭眼笑、头微微上抬、脸红——形变过渡几乎完美；
- **道具换了**（书换成笔记本）：形变能过，道具会在中段交叉溶解，可以接受；
- **手离开原位去拿别的东西**（从书移到杯子，位移 100px 以上）：光流跟不上，会把原来那样东西一起拖走，
  这一对 morph 会被自动拒掉、退回淡入淡出。要连续就拆成关键帧链（见下节），每步只走一小段；
- **大动作**：趴下这类位移超过自身宽度一半的，同样拆成关键帧链（入睡 = 看书 → 书放低一半 → 打瞌睡 → 快睡着 → 趴下），
  落点姿势标 `morph: false`、`slow: true`；转身、站起来这类网格形变做不到的，见 `pitfalls.md`「什么时候这套方法不够」。

## 关键帧链怎么出

- **先画布局图**：在 anchor 上每帧画一格，框出这一帧的手、道具和「另一只手里不动的东西」，坐标写进 brief。
  道具的位置从场景量：场景部件的框经座位变换换算到画布上（第一个案例里桌上的杯子在画布 x 1128–1353、y 864–1071，
  底部超出了画布）。
- **交接帧照版式图出**：握杯那一帧给一张「上一帧 + 场景里的杯子按原位贴上」的图当编辑底稿（写明是版式参考、要整张重画、
  不交付），要求杯子不挪、手握住把手；拿起那一帧从最好的握杯帧编辑，同一只杯子竖直抬起、x 不变，写明抬多少；
  再往后一帧从最好的拿起帧编辑。三帧放进同一批按顺序出（后一帧编辑前一帧的最佳候选），闸门「杯子在框内 ±8px」。
  第一个案例：不给底稿、只给框，三批候选画的杯子都偏左 100–200px，交接时两只杯子；给了底稿，握杯帧三张都画在原位（位移 0–1px）。
- **每步等距、够小**：道具每步不超过它宽度的 60%；手离开原位的第一步单独成帧；从「双手捧书」到「单手放低书」也单独成帧。
- **不动的部分每帧写同一个框**：另一只手拿着的书、头的位置——链上的帧之间只该有这一步的变化。
- **分批并行**：链长时拆成两批（前半 / 后半），两批的 brief 共用同一段约定（书在哪、哪只手），各自只出自己那几帧。
- **挑整条链**：`pick --sequence`，不单张挑；某一步对不上时只重出那一步两边的帧。
- 生成方的自检门槛会比项目严（比如要求道具在框内 ±25px），它标 `-reject` 的候选照样拿来量——以项目的闸门为准。

## 生成方要交的自审报告

要求出图方（人或 agent）对每张给出：尺寸、是否真透明（透明像素数）、主体包围盒、相对 anchor 的肩线漂移（固定几列测量）、
截断线位置、闭眼帧眼外变化、肉眼可见的缺陷（多指、眼镜断、发丝边缘脏）、重出了几版、为什么选这一版。
**采信它的测量，不采信它的结论**——结论由 check 和你看证据图来下。

## 每张出几个候选，按测量挑

同一条 prompt 每次漂得不一样，所以稳定的做法不是「出一张、不行再出」，而是**每张一次出 3 个候选**，用
`python rig.py pick --config rig.json --pose <姿势> --files <候选…> [--fit head]` 挑：它给每个候选做 check 的验收，
再量它和 anchor 的一致性——头按脸框对上（`--fit head`，给本来就要动头的姿势）、几何对齐之后，头发轮廓还剩多少对不上。
那个残差就是生成模型**画得不一样**的东西，对齐救不回来，所以它越小越好。闭眼帧用 `--open <睁眼帧>`，按眼外变化打分。

分数只量得到轮廓和位置，量不到动作对不对：第一个案例里，得分并列第一的写字候选把眼睛画成了闭着的，
写字要的是睁眼往下看。**挑出来的前两名，要人看一眼 `review/pick-<姿势>.jpg` 再定。**
选定的那张改成正式文件名放进 source，其余候选留在出图批次目录里备查。

## 什么时候重出、什么时候接受

| 情况 | 处理 |
| --- | --- |
| check FAIL（假透明、肩线 > 8px、截断线 > 8px、尺寸不对） | 重出这一张，原稿加后缀保留做对照 |
| 闭眼帧被 check 拒（成块变化 > 1% 或整体 > 15%） | 重出闭眼帧；来不及就接受「这个姿势不眨眼」，记进已知问题 |
| 肩线 3–8px（WARN） | 看 overlay：双线不明显就接受 |
| 动作幅度没达到设计（比如「缩一下」没画出来） | 这是设计取舍，报告里写明，不假装做到了 |
| 纠正稿反而更差 | 回到上一版，别为了「重出过了」而用更差的 |

## 用图片 API 的遮罩编辑出帧

出图方能用遮罩编辑（OpenAI Images API 的 edits + mask 这类）时，anchor 之外的帧都在 anchor 上带遮罩改：眼睛帧只开两只眼睛和眼睑那一带，
头部动作只开头和耳朵，身体、胸毛、爪子、尾巴盖住。第二个案例（一只趴着的猫，三个画风各 6 张）实测：

- 眼睛帧（闭眼、半眯、看你）眼外变化 1–2%，align 后 ≤ 1.4%，换帧看不出身体在闪；不带遮罩时整张会被轻微重画一遍。
- 模型不完全守遮罩：轮廓那一圈毛边、几根胡须常被重画，属于对齐修得回的那类。
- **大动作帧守不住角度和斑块**：要「头后仰 6° 打哈欠」，三个画风都仰了 20–30°，有的还改了头顶的斑块，重出也没改过来；
  光流过渡中段会有一瞬双脸，最大的那家被 morph 拒掉、退回盖上再淡出。要这类帧，遮罩只开嘴和眼（头的轮廓盖住），再在运行时用头部网格补那几度仰头。
- 全新生成（anchor 候选）时模型反复把动物的眼睛画成带眼线、眼白的人眼；先按目标构图摆一张身份参考当第一张输入图，取景能一次到位，眼睛再用遮罩修。
- 拿透明精灵图去编辑前，先把它压到中灰、保留 alpha：**每个像素按自己的 alpha 合成到中灰**（`rgb·a + 128·(1−a)`），不是只把全透明的改灰——
  半透明的那一圈底下同样藏着光晕。第二个案例：只改了全透明像素的那批 3 张全都整只放大了（0.85–4.6%，平移 6–37px）；
  按 alpha 合成的那批 3 张里 2 张 ≤ 0.5%、1 张 3%。放大和平移 align 修得回，但漂得多的那张遮罩外的毛也重画得多，挑候选时先量（全局相似变换 + 对齐后的颜色变化）。
- 只开嘴、下颌、胡须垫和眼睛的遮罩画哈欠（头的轮廓、耳朵、斑块盖住）：第二个案例四张候选头全没动（上一轮开整颗头的遮罩，三个画风都仰了 20–30°）。
  遮罩外的毛会被重画一些（全局对齐后 13–16%），align 的 `align_to` + `free`（眼带 + 嘴框）对齐后降到 2–3%。

**模型做不到的三件事**（第二个案例实测，别再花钱试）：

| 要的 | 结果 | 改用 |
| --- | --- | --- |
| 部位大一点（眼睛放大 12%），遮罩留了余量 | 画成约 1.5 倍、睁圆了，「软半眯」没了 | 不生成：按部位中心做局部放大镜变换（只重采样、不改色），所有带这个部位的帧（睁 / 闭 / 半眯 / 看你）用同一个变换，天然对得上 |
| 同上，遮罩收紧到只够放大 12% | 整只重画放大约 13%（遮罩外变化 50%） | 同上 |
| 只改一根线（眼睑边改成暖棕） | 两只眼睛画成了黑洞 | 不改；要么接受原画，要么整只眼睛按设计重出一套 |

遮罩给多大，模型就画多大；要的是「同一张画稍微改一点」时，先想能不能用几何算出来。

## 动物的表情

用户给的性格词（第二个案例：微胖、憨厚、安静、乖巧、可爱、有点懒）要落到眼睛和嘴的几何上，否则模型默认画「酷」的猫：

| 读起来 | 几何上是什么 | brief 里怎么写 |
| --- | --- | --- |
| 阴险、狡猾（要避开） | 眯眼 + **外眼角上挑** + 眼神斜着瞟 + 嘴角上扬 | — |
| 憨、乖、懒 | 眼睛圆一点、**眼角平**（外眼角不高于内眼角）、眼神落在前下方、眉心和嘴角放松、脸颊圆 | 「soft round eyes, level eye corners, relaxed brows, gentle sleepy look, not sly」 |

- 改表情用脸部遮罩（眼、眉心、嘴）在 anchor 上编辑，其余盖住；第一轮的 anchor 读起来阴险，只改脸就救回来了，不用重出整只。
- 半眯、闭眼帧也要写「眼角平」：第一轮半眯 / 闭眼的外眼角是斜的，闭上像在冷笑，重出时加了这一句才平。
- 挑候选时把几张放在同一个取景里并排看「像不像这个性格」，数字量不到这个。

## 动作的时间先调研

一个有真实参照的动作（打哈欠、伸懒腰、甩头），先让出图方（能上网的 agent）查真实视频和动画参考，交一张**阶段表**：
每一段多长、眼睛 / 嘴 / 头 / 耳朵各在做什么、哪段快哪段慢，再按表定链上要几张帧、每步多长。凭感觉定的时间读起来是机械的。
第二个案例（猫打哈欠，9 段约 3.6s）：眼睛先闭、嘴慢慢张开、张满停一下、合得比张得快、眼睛最后睁开——直接写进了 `creatures.md`「哈欠」。

## 为什么不用视频 / GIF 生成

视频模型一次生成一段连续动作，帧间确实比逐张生成稳；但它生成的是**一段固定的录像**，不能按运行时的状态随时进出、
被打断、和呼吸叠加，而且每段的首尾帧要和姿势图完全一致才能接上，这又回到了一致性问题。
用图片模型生成 GIF 没有意义：GIF 只是把逐张生成的图装在一个文件里，每帧照样漂。
视频模型可用时，比较值得的用法是：生成两个关键姿势之间的**参考动作**，从中挑一两帧作为中间姿势，再走本流水线。

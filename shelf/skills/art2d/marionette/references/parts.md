# 部位、跟随与分层：对照 Live2D 的做法（分支能力）

用户要「Live2D 的拆分细度和流畅程度」时读这份：Live2D 的流畅来自哪里、我们已经有哪几样、差的几样按什么顺序补，以及要不要用它的编辑器。

## 结论：学它的数据模型，不用它的编辑器

Live2D 的观感来自它的**数据模型**：很多块单独画的部件（被挡住的地方也画出来）、一棵变形器的树、每个参数两三个关键形状、摆的物理、
动作曲线。这套模型可以照做。它的编辑器不行（2026-11 查证）：

- 没有命令行，也没有能造模型的接口：正式版的外部接口只能读写参数值；5.4 alpha 的编辑接口能加参数、关键点、部件和变形器，
  但不能建网格、不能设顶点和变形器的控制点，也碰不到物理和动作。真正让模型流畅的「捏关键形状」，哪个工具都没自动化
- `.moc3` 是封闭格式，官方只公开 JSON 那几种（motion3、physics3）；第三方写 moc3 的工具存在，但许可协议禁止逆向，法律状态没人说清
- 让 agent 用界面点着做：公开的一次尝试估了 140–220 小时，每一步还要人批准
- 网页运行时是「开源框架 + 闭源核心」，PixiJS v8 只有社区分支

所以路线是把自己的 rig 往 Live2D 的数据模型上长（下面的对照与路线），数据全是 JSON，照旧用逐帧截图量。备选是 **Spine**：
JSON 格式公开、可以手写，有官方 PixiJS v8 运行时和物理约束；要买 Professional（网格在这一档），运行时要求持有编辑器许可。
自己的数据结构保持能转成 Spine JSON，就不被锁死。

## 对照：它有什么，我们有什么

| Live2D | 我们现在 | 差什么 |
| --- | --- | --- |
| **部件**（ArtMesh）：每块单独画，挡住的地方补画完整 | 一个姿势一张整图、一张网格；部位是多边形 + 权重（**软拆分**：头、耳、尾、躯干各动各的，但不能互相错开） | **真分层**：头、躯干、尾各一张带透明度的图，被挡住的地方补画；错开时不拉伸、能露出后面 |
| **变形器**：warp（贝塞尔网格）与 rotation，成树 | 绕根旋转（`moveLimb`：角度 × 权重，可推、可压）；呼吸是权重图上的位移 | 父子层级（头的变形带着耳朵和脸上的部件）；warp 的关键形状 |
| **参数与关键形状**：一个参数 2–3 个 key，中间插值；blend shape 叠差值 | 时间函数直接写在代码里（哈欠表、眼睛步骤） | 命名参数（Breath、HeadX、TailSway…）+ 每个参数的关键形状 + 叠加 |
| **物理**：输入参数 → 摆链 → 输出参数（时长、易摆度、反应时间、收敛） | `follower`：临界阻尼弹簧，跟着一个值晚一点、小一点到（头跟呼吸） | 链式的摆（尾巴一节带一节）、输入输出的映射表 |
| **动作**：每个参数一条曲线（线性、贝塞尔、阶梯） | 表驱动（每步：到哪张、多久、什么缓动） | 通用的曲线段；随机触发在它上面 |
| **剪裁蒙版、乘色** | 受光滤镜；部位的轮廓每帧画进离屏图，滤镜里算投影（`references/shading.md`） | 分层后直接用部件自己的透明度当投影的轮廓，毛边是真的 |
| **换画**：部件透明度 100 / 0 切换，淡的时候两张叠着 | 相邻两张图量光流、形变着换，份额相加的溶解 | 这一样我们更强：没有叠影 |

官方手册没有给动物或毛发的拆分建议；人的清单是：前发 / 侧发 / 后发加每一绺单独会动的头发、睫毛、眼珠、眼白、眉、鼻、上下唇、
口腔、脸轮廓、耳、脖子（往脸底下多画一截）、躯干、上臂 / 前臂 / 手、腿。「不补画，动起来就像断开」。

## 呼吸：从身体起，头慢一点

整张图一起缩放，是一只被打气的球（用户 11-15）。呼吸的起点是躯干：

- **躯干**：从它压着的那一行（不动）往上，抬升渐渐加到肩；肋部向两侧微微张开，张得最多的在髋和肩的中间
- **头**：不跟躯干同相。把「它脚下那一截抬了多少」喂给一个弹簧，头按弹簧的输出走——晚约 0.3–0.5 秒、幅度八九成。
  权重图里头那一块的同相份额要去掉（`head_weight: 0`），不然两份叠在一起、滞后看不出来
- **尾、耳**：不随呼吸；它们有自己的摆动

```ts
const headBob = follower(5.5);                       // rad/s：越小越慢
const lift = breathPx * 0.5 * (1 + Math.sin(phase)); // 背此刻抬了多少
head.push.y = -headBob.to(lift * 0.24, dt);          // 头：小一点、晚一点
```

弹簧用隐式积分（任何帧时间都稳）。对周期 T 的呼吸，临界阻尼弹簧的滞后约 `2·atan(2π / (T·ω)) / (2π / T)`：T = 2.9 s、ω = 5.5 时约 0.35 s，
幅度约 0.86。Live2D 里同样的事是「把呼吸参数接进物理的输入、反应时间决定滞后」；它的 SDK 示例让呼吸和头的几个角度各用不同的周期，
本来就不一起动。

背面坐着的动物（没有脸要动）同样做：一张网格，躯干、头、尾三块权重；头的权重从脖子（根）到头顶（尖）渐满。

## 路线：按这个顺序补

每一步都要过逐帧验收（SKILL.md 第 9 步），前一步没过不做下一步。

1. **软拆分 + 跟随**（已有）：部位权重、绕根转、头跟呼吸的弹簧、尾巴两道弯。够用于呼吸、摆尾、哈欠、被摸
2. **真分层**：先定部件清单（趴着的猫：头连耳、躯干、尾；背面坐着：头、躯干、尾）。每块的蒙版用多边形起草、按颜色或抠图模型修边；
   被挡住的地方用遮罩编辑补画（「去掉头，把后面的胸毛接着画」）。**验收：各层叠回去等于原图**（逐像素差在阈值内），
   不等就不收。分层之后，头抬、头歪不再拉伸脖子，投影直接取头这一层的透明度
3. **参数与关键形状**：把代码里的时间函数换成命名参数；一个参数两三个关键形状，组合用叠加的差值，不做 3×3 的全组合
4. **摆链与动作曲线**：尾巴、耳朵、胸毛接到同一套摆上，输入是呼吸和头的参数；动作写成曲线；随机触发放在最上面
5. **用到人物身上**：脸是最难的一块（五官各自的视差），先做头发和身体

**头转过来露出侧脸**这类动作，在哪个工具里都要一张新画：没画过的脸颊，变形变不出来。Live2D 的头转是把脸上各部件按不同的量平移、
远侧收窄，标准范围 ±30°，而且只有正脸有自动生成。背面转成侧脸：画一张转过头的头，和原来那张量光流、形变着换（我们已有的做法）。

## 毛要不要拆成一块块

Live2D 的头发是一绺一张图、各接一条摆。毛团照这样拆，每一团都要补画底下那一层，团和团叠着的地方透明度很难干净。先不拆，按这个顺序：

1. 阴影落在毛缝里（`references/shading.md`）——不拆也能做到「影子在毛里」
2. 分层后，胸毛、颊毛这种**成片会动**的毛作为一个部件，接到摆上跟着头晚一点动
3. 只有特写里明显该单独动的几绺（耳尖的长毛、尾巴尖）才单独拆

## 自动拆层的工具（2026-11 的情况）

都没在「画出来的、非动漫的动物」上验证过，用之前先在自己的图上试一张、按「叠回去等于原图」验收：

- See-through（Apache-2.0，8–16 GB 显存）：一张动漫人物图拆成最多 23 层并补画；作者自己说它还不是「图到 Live2D」
- Qwen-Image-Layered（Apache-2.0，有托管接口）：拆成若干 RGBA 层；头发常是一整层，提示词管不了怎么拆
- 抠图模型（SAM 一类）：只给蒙版，不补画
- 研究原型（从分层人物预测关键形状的、从肖像或文字生成 Live2D 脸的）：都围着动漫人物

## 手工 Live2D 仍然更好的地方

凭眼睛捏出来的关键形状（让人信服的头转）、同一只手补画的隐藏处、很多绺毛叠着时干净的透明度、凭手感调的物理、面捕和画师的生态。

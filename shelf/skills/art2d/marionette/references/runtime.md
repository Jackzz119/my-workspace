# 运行时：让导出的 rig 在引擎里活起来

> 按需加载。接入运行时、换引擎、调时序与运动幅度时读。模板：`../templates/runtime/`。

## 分层

```
行为导演  rig-director.ts   真实状态 + 反应 → 现在该显示哪个姿势          （纯逻辑，可重放测试）
核心      rig-core.ts       姿势切换状态机、眨眼节奏、顶点变形、数据解码    （纯逻辑，与引擎无关）
适配层    rig-pixi.ts       加载清单与贴图、每个姿势一张网格、把核心的数推进网格（引擎相关）
```

核心和导演都不自己读时钟、不自己取随机数：调用方传 `nowMs` 和 `random`，所以任何一段行为都能在测试里原样重放。

## 每帧做什么

```
pose = director.update(now)                 // 状态 / 反应 → 姿势
if (pose !== view.current()) view.show(pose, animate = true)
view.update(elapsedSeconds)                 // 切换进度、眨眼、每个可见姿势的顶点变形
```

`view.update` 里：`switcher.frame(now)` 给出每个可见姿势的 alpha 和形变位移；
`blinker.closed(now)` 决定当前姿势用睁眼还是闭眼贴图（形变进行中不眨）；
对每个可见姿势调 `deformVertices(rest, positions, weights, t, motion, shift, amount)`。

## 姿势切换：两条路

**形变**（清单里有这一对的双向形变场）：420ms，easeInOut。

| 进度 t | 旧姿势 | 新姿势 |
| --- | --- | --- |
| 0 → 1 | 顶点沿 a→b 移动 e·d（e = easeInOut(t)） | 顶点从 b→a 的 (1−e)·d 松回原位 |
| 0 → 0.25 | alpha 1 | alpha 0 |
| 0.25 → 0.75 | alpha 1 | alpha smoothstep(0.25, 0.75, t) |
| 0.8 → 1 | alpha 1 − smoothstep(0.8, 1, t) | alpha 1 |

形状全程在走，图像只在中段交换；旧姿势等新姿势完全盖住（t ≥ 0.75）后才开始淡出，
所以光流没弯到位的残余是「软着陆」，不会在最后一帧啪地消失。

**盖上再淡出**（没有形变场）：新姿势画在最上层，180ms 淡入；旧姿势全程不透明，180ms 时开始 120ms 淡出。
标了 `slow` 的姿势（入睡 / 醒来）用 400ms + 300ms。

**慢速形变**（有形变场、且其中一个姿势标了 `slow`）：900ms，新姿势在 35%–65% 之间显形，盖满后旧姿势在 70% 之后淡出。形状走得更久，读起来像打盹；换图窗口更窄，两张半看半不看叠着的时间只有约 270ms。窗口由 `morphSwap()` 给出，流水线的离线模拟用同一组数。

**关键帧步**（切换带了导演给的 `transition`）：时长和缓动按那一步，新姿势只在 42%–58% 之间显形（340ms 的一步约 55ms）。
链上的步又短又多，连续性由网格形变负责；光流没跟上的东西（被端过胸前的杯子）在换图那一刻会同时露出两份，窗口越宽露得越久。
第一个案例：窗口是 25%–75% 时，喝一口约一半的帧能看到两只半透明的杯子，收窄后每步最多一帧。

两条路共同的不变量：**任何时刻，最上层没到不透明时，它下面一定有一张完全不透明的**。
这是闪烁问题的根：两张同时半透明，场景从人物身上透出来，眼睛读到的是「人消失了一下」。
模板的测试逐 4ms 检查这条不变量，改时序时要保住它。

**在角色自己的图层里溶解**（角色整只先画进一张离屏图时，比如挂着受光滤镜——滤镜的输入纹理一开始是全透明的）：
盖上再淡出在普通混合下有一个余量——两张网格叠着时，半透明的软边（毛边、发丝）被叠了两层，覆盖率从 a 变成 a + a(1−a)，
旧的那张撤掉时又变回 a；只有旧图有的部分（张大的下颌）在它最后 20% 里才淡掉。毛茸茸的轮廓上这两样都看得见：
链的每一步末尾整圈轮廓闪一下。改法：

- 每个姿势网格用**加法混合**（Pixi：`mesh.blendMode = 'add'`），只画进角色自己的图层；
- 每帧把份额归一：当前姿势用切换器给它的 alpha `m`，其余姿势按各自 alpha 的比例分掉 `1 − m`；
- 预乘颜色相加 = A·(1−m) + B·m，内部覆盖率恒为 1（不透底），软边是两张的线性插值（不叠厚），只有一张有的部分随 m 均匀淡入淡出。

形状照旧由形变场带着走，只有换图从「盖上」变成「溶解」，窗口还是切换器给的那段（宽窗口 25%–75%）。
图层外面（和场景合成）照常是普通混合。第二个案例（猫，哈欠链 12 步）：120fps 下，这一条加上眼睛的单网格混合（「眨眼」），小跳 23 处 → 0，每帧最大变化 0.79 → 0.37。
角色没有自己的图层（直接画进场景）时不能这么做——加法会把场景也加进去，仍走盖上再淡出。

**打断**：切换进行中又来一次切换，先让当前形变立刻落地（旧 0、新 1），再开始新的一次；
半弯的网格不叠加。回到一个还在交接中的姿势，它直接重新淡入。

## 关键帧链

导演（`rig-director.ts`）里一个反应可以是一条链（`sequence`），一个状态可以带进入链（`enter`）：

| 规则 | 为什么 |
| --- | --- |
| 所有链的相邻帧连成一张图：两个姿势之间只要图上连得通（写字 ↔ 摸头、睡着 ↔ 看书），姿势变化就沿最短的一串帧一步步走 | 链上的形变场只在相邻帧之间；绕过中间帧直接跨过去，就是溶解和残影 |
| 链总从 `frames[0]` 出发：图上连得通就沿图走过去，连不通（别的反应姿势）就用 `returnMs`（默认 700ms）慢慢回去；链整段播放，别的反应一律不接（`react` 返回 false） | 喝到一半被戳，从「杯在嘴边」直接变成「大笑」没有可用的过渡 |
| 状态变化时先把正在播的链沿图收回它的 `frames[0]`（每步 0.7 倍时长），再沿图走到新状态的姿势；状态和反应自己的走位不能被别的反应打断，「回到原姿势」的走位可以 | 杯子要先放回去，人才能离开 |
| 进入带链的状态（入睡、放下书写字）按链往前走，离开时沿图倒着走；按住类的链（摸头）走到最后一帧后停住，松手再沿图走回 | 同一组帧用两次 |
| 链的第一步缓入、中间匀速、最后一步缓出（`in` / `linear` / `out`，衔接处速度相同） | 一步一停就成了机器人；整条链是一个手势 |
| 每步默认在 42%–58% 的窄窗口里换图；链写了 `swap: "wide"` 就在 25%–75% 换（导演把它放进每一步的 `transition().window`） | 窄窗口是给「网格带着动作走」的步；头不动、嘴张开这种步，光流几乎为零，60ms 的换图就是嘴一下跳出来 |

视图每次换姿势时问 `director.transition()`，拿到这一步的时长和缓动传给 `show()`；返回 null 就用默认（420ms 缓入缓出）。
递咖啡这类「用户给的」反应被更强的反应挡住时，业务层可以排队几秒再试，不要丢。

## 手里的场景道具

视图的 `part(name)`（核心 `partFrame`）每帧给出场景部件的 `{ alpha, dx, dy }`：场景把部件画在原位加 `(dx, dy)` × 画布缩放处，
透明度设成 `alpha`。规则按形变的这一步两头的姿势定：

| 这一步 | 部件 |
| --- | --- |
| 两头都不 `hides`（伸手 → 握杯） | 不透明，位移从前一帧的 `holds` 插到后一帧的（握杯帧把它轻推到画出来的那只上） |
| 走进 `hides` + `holds` 的姿势（握杯 → 拿起） | 沿两帧的 `holds` 跟着手走，全程不透明，进度 85% 之后才淡出：两只杯子一直叠着，换图看不见 |
| 走出这样的姿势（拿起 → 握杯） | 从手里的位置出发，进度 15% 之前就淡入到不透明，再跟着手放回原位 |
| 走进只 `hides` 不 `holds` 的姿势 | 退化：随这一帧的显示程度淡出（两只半透明的杯子会同时出现，交接帧要重出） |
| 两头都 `hides`（拿起 → 胸前 → 喝） | 不画 |

位移的插值用这一步的缓动进度 `e`（和网格形变同一个数），所以部件和画出来的手同速；进度由切换器的 `progress()` 给出，
必须在 `frame()` 之后取。部件上附带的效果（杯口的蒸汽）跟着同一个 `alpha` 和位移走。

## 眨眼

闭眼 140ms，间隔 2.4–6.5s 随机，15% 概率连眨（第二下间隔 180ms）。换姿势后重新计时。
形变进行中暂停（闭眼贴图会换到正在弯的网格上）。例外：一段有意安排的眼睛序列（哈欠前先闭眼）在形变中照走——
新姿势用此刻的眼睛图，**被换下的姿势保留它最后那张**，别在它让位的那几百毫秒里把眼睛弹回睁开。

**眼睛图之间要淡、不要跳时**（动物有四张眼睛图，半眨、慢眨都是它们之间的过渡）：在**同一张网格里混两张图**，
不要再叠一张共用几何的网格淡入。叠的那张和底下那张的软边叠成两层，淡完撤掉的那一帧轮廓整圈变薄——
第二个案例每次换眼睛末尾一帧小跳，120fps 才量得出。做法：

- 网格换一个自定义着色器：两个纹理（当前显示的、正在进来的）+ 一个混合量，片元 `mix(texture(uTexture, uv), texture(uNext, uv), uMix) * vColor`；
  覆盖率始终是一张图的，眼睛那一块按 uMix 平滑过去；淡完把「进来的」设成「当前」、混合量归 0，画面不变
- 一次只淡一样：正在淡的时候又要换别的眼睛，等这次落地再开始下一次（最多晚一两百毫秒），不从半路跳回去
- PixiJS v8：`new Shader({ glProgram, resources: { uTexture, uNext, 一组 { uMix } } })`，再给它挂一个 `texture` 字段（网格的着色器类型要它，
  也用来定混合模式）；顶点着色器自己算位置：`uProjectionMatrix * uWorldTransformMatrix * uTransformMatrix`，颜色 `uColor * uWorldColorAlpha`
  （这些全局 / 局部 uniform 由网格管线按名字填）；`MeshPlane` 照常改顶点，`mesh.shader = shader` 即可。参考实现登记在项目文档里

## 手势：反应里的身体

换一张图只换了表情，身体是僵的——被戳只「笑一下」就是这个感觉。手势是一组随时间变化的曲线，叠在 idle 之上：

| 项 | 作用于 | 含义 |
| --- | --- | --- |
| `lift` | 呼吸权重 | 身体上抬（px，+ 向上） |
| `lean` | 呼吸权重 | 上半身绕 `pivotY` 倾斜（弧度） |
| `hairX` | 头发权重 | 头发额外的横向甩动 |
| `hairLag` | 头发权重 | 头发比身体慢半拍（= 身体现在的高度 − 70ms 前的高度），所以身体一动头发就弹 |

权重图决定谁带着动：肩和头随手势动，捧着的书、搭在桌上的手不动，头发晚一点跟上。
内置两个（按约 1000px 高的半身像定的幅度，换尺寸按比例缩放）：

- `flinchLaugh`（1.3s）：80ms 内上抬 9px 并往后一仰，随后约每秒 4.5 下「哈哈」的肩膀颤动（4.5px 起、520ms 衰减），头发横甩；
  实测显示尺寸下先一缩约 4.7px，再是逐渐变小的几下笑颤；
- `startle`（0.6s）：只一缩，不笑。

规则：同时只跑一个，新的替换旧的；最后 200ms 自动收回到 0，接回 idle 不跳；减少动效时不播。
和姿势切换同时发生没问题——手势加在形变位移上面，形变照走。
新增手势时保持：峰值出现在 100ms 以内（反应要「即时」），每 4ms 采样相邻差 < 1px（测试会查），结束时回到 0。

## idle 运动参数

画布 px / 弧度 / 秒。默认值来自一个 1377×1015 画布的半身像，显示时约 0.57 倍；换尺寸按比例换算。

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `breathPx` / `breathS` | 3.2 / 3.6 | 呼吸：按呼吸权重上抬，正弦 |
| `leanRad` / `leanS` | 0.004 / 7.4 | 上半身绕 `pivotY` 的微摆，只作用于随呼吸动的部分 |
| `hairPx` | 4.5 | 发梢最大位移 |
| `hairS` | 4.2 / 2.3 / 3.1 | 三个互质的周期叠加，看不出循环；相位沿 y 往下传，发梢跟着发根走 |
| `pivotY` | 画布底 | 微摆的支点（坐姿 = 截断线） |

**宁小勿大。** 显示尺寸下呼吸约 2px、发梢 2–3px 就够「活」；再大就变成晃。
微摆只给会摆的身体：坐着的人上半身有；趴着的动物身体不摆（`leanRad: 0`），只有头和尾巴轻摆（`references/creatures.md`）。

## 受光

基础是场景给所有活物的同一个 tint（时辰 × 天气，关灯时再混一层冷暗）——和坐在对面的人一样。更准的是 gaffer 在角色待的位置
**量出来**的光（每张底图一个增益，可以大于 1）；单独画的浅色角色还要先把增益的色度和高光收一收（gaffer `references/runtime.md`「活物的场景光」）。
紧挨着光源的角色再叠一层小范围滤镜，只盖它自己的包围盒，仍然一个像素都不画进图：

| 项 | 怎么算 | 跟着什么变 |
| --- | --- | --- |
| 方向光 | 以量出的光为中心：朝光源一侧亮而暖、远侧同样多地暗而冷，平均下来还是量出的那个光（量的值里已经含了灯的平均份额，不能再整体加一遍）；朝向沿「角色中心 → 光源」投影，用平滑阶梯从远侧 0 到近侧 1 | 开关灯、灯被调暗（对方睡着）；时辰：光源在日落时几乎不算数 |
| 轮廓光 | 透明度沿「朝光源」方向往外取三步，边缘那几像素加一道光源色 | 同上 |
| 环境轮廓 | 朝窗（上方）的边加一道很淡的天色 | 时辰 |
| 底部 | 贴桌那一截暗 14% | — |
| 影子 | 贴桌的窄深接触影一直在（灯越亮越深）；背光一侧的软投影只跟着灯 | 开关灯 |

光源的位置用场景坐标给（灯泡在灯罩里的位置），每帧换算到屏幕；滤镜的输入是预乘 alpha，先除再乘。数值和实现以项目登记的参考实现为准。

部位投在身上的影子（下巴压在胸口上那一带）也在这个滤镜里算：每帧用姿势自己的网格把头、尾巴的轮廓画进一张小离屏图，
滤镜里「往背光方向推开的轮廓减去轮廓自己」，两边都软。做法、参数和试错见 `references/shading.md`。

## 适配层的职责（换引擎时照这个清单写）

1. 每个姿势一张网格：**铺满整张画布**、`floor(w/grid)+1 × floor(h/grid)+1` 个均匀分布的顶点，
   UV 与顶点一一对应（和导出时的采样位置一致）。记下静止位置 `rest`。
2. 眨眼只换贴图（要淡就在着色器里混两张，见「眨眼」），网格不重建（Pixi 里要关 `autoResize`，否则换贴图会按贴图尺寸重排顶点）。
3. 每帧把核心给的 alpha 写进网格，调 `deformVertices` 改顶点，通知 GPU 顶点缓冲更新。
4. 切换时把新姿势放到最上层。
5. **第一次切换前把所有贴图上传 GPU**（Pixi：`import 'pixi.js/prepare'` + `renderer.prepare.upload`，**不要 await**——
   页面在后台时它可能一直不返回）。首次用到才上传的贴图会卡住它出现的那一帧，看起来就是人物消失。
6. 场景光：给所有姿势网格统一乘一个 tint（时辰、开关灯）。
7. 数据 PNG 读原始字节：`createImageBitmap(blob, { premultiplyAlpha: 'none', colorSpaceConversion: 'none' })`，
   不要走会做色彩管理或预乘的加载器。

各引擎的网格：

| 引擎 | 网格 | 改顶点 |
| --- | --- | --- |
| PixiJS v8 | `MeshPlane({ verticesX, verticesY })` | `geometry.positions` + `getBuffer('aPosition').update()` |
| Three.js | `PlaneGeometry(w, h, cols-1, rows-1)`（注意 y 轴朝上，要翻） | `attributes.position` + `needsUpdate = true` |
| Unity | 自建 Mesh（`vertices` / `uv` / `triangles`），`MeshRenderer` + 透明材质 | `mesh.SetVertices` 每帧 |
| Godot 4 | `MeshInstance2D` + `ArrayMesh`，或 `Polygon2D` 的 `polygon` | 每帧重写数组 |
| Canvas 2D / 无 GPU | 不适用网格；可按三角形 `setTransform` + `clip` 画，成本高，只适合很小的人物 |  |

## 行为导演

```ts
const director = createDirector(
    {
        statePose: { reading: 'reading', writing: 'writing', asleep: 'asleep', away: null },
        enter: { asleep: manifest.sequences.doze, writing: manifest.sequences.write },
        reactions: {
            glance: { pose: 'glance', priority: 1, seconds: [2.5, 4], in: ['reading'] },
            sip: { sequence: manifest.sequences.sip, priority: 2, in: ['reading', 'writing'] },
            // the same reaction over what the hands hold in that state: never a prop swap
            poked: {
                pose: 'poked',
                poseIn: { writing: 'poked-writing' },
                priority: 3,
                seconds: 1.4,
                in: ['reading', 'writing']
            },
            patted: {
                pose: 'patted',
                poseIn: { writing: 'patted-writing' },
                priority: 4,
                seconds: 0,
                in: ['reading', 'writing']
            }
        },
        idle: [
            { reaction: 'sip', every: [90, 180], in: ['reading'] },
            { reaction: 'glance', every: [20, 60], in: ['reading'] }
        ]
    },
    'reading',
    random,
    performance.now()
);
```

规则：反应不打断优先级更高的；同一反应再来一次是延长；反应只在允许的状态里发生（空椅不能戳）；
自发小动作从「上一次回到状态」开始计时；按住类（摸头）`hold(kind, true)` 期间一直保持，松手后停留 0.8s。
反应**不许换掉手里拿的东西**：写字时被戳、被摸头，要有一张「笔还在本子上」的变体（`poseIn`），
不然切过去就是本子溶解成书；这种变体只改脸和头，是纯局部形变。
**状态只来自真实事件**（在线、正在输入、主动设置），不因为「一会儿没操作」就编一个状态。

## 触碰

- 头部区域：按下后移动超过约 12px = 摸头（`hold(true)`），松手 `hold(false)`；按下不动就松开 = 戳；
- 身体区域：点一下 = 戳；
- 区域用姿势画布坐标定义（换算到屏幕），人不在（空椅）或睡着时关闭；
- 触碰区要在所有别的可点击层之上，但不能挡住 UI。

## 画质

- **按屏幕实际像素密度渲染**（最多 3 倍，并给总像素设上限），不要封顶 2 倍：3 倍屏会被浏览器再拉伸 1.5 倍，线稿发糊发锯齿。
- 任何滤镜（调色、天气）的分辨率要跟随画布（Pixi：`resolution: 'inherit'`、`antialias: 'inherit'`），
  否则滤镜按 1 倍渲染，整幅画面被压低再拉回；滤镜是无操作时直接不挂。
- 人物素材按最大显示尺寸的 1.5–2 倍出图；素材精度不够时，提高渲染倍率也救不回来。

## 可访问性与性能

- 用户开了「减少动效」：关掉 idle 运动和形变（切换直接换），保留眨眼——适配层模板的 `reducedMotion` 选项，接 `prefers-reduced-motion`。
- 页面隐藏时停掉 ticker。
- 顶点数：58×43 ≈ 2500 个 / 姿势，每帧只算可见的 1–2 个，CPU 成本可以忽略。

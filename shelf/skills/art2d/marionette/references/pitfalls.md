# 踩过的坑：症状 → 原因 → 解法

> 按需加载。人物动画出问题时先查这里。每一条都是生产案例里真实发生过的（第一个：坐在桌后读书的人；第二个：趴在桌上的猫）。

## 切换姿势

**切到某个反应时头发多出一块（形变过渡后也还在，只是变柔和了）**

- 原因：不是过渡的问题，是**这张图本身**：反应姿势是「编辑 anchor」生成的，发型轮廓还是胖了一圈（第一个案例里右侧发缘整条外扩约 10px）。
  形变只会让多出来的部分慢慢长出来，消除不了。
- 解法：`align_to` 把反应帧的几何对齐回 anchor（只有脸可以不同）；对齐后 `align-<姿势>.jpg` 上还成块的红色是**多画的内容**，重出那一张。

**反应很干：只是换了张脸**

- 原因：身体没有任何动作。
- 解法：配一个手势（`GESTURES.flinchLaugh` 等），幅度按显示尺寸检查——画布上 2–3px 的颤动在屏幕上约 1.5px，基本看不见。

**人物闪一下，像消失了半秒**（尤其摸头这种一点就切的）

- 原因 1：新旧两张同时半透明交叉淡化，场景从人物身上透出来。
- 原因 2：新姿势的贴图第一次用到才上传 GPU，出现的那一帧卡住。
- 解法：盖上再淡出（新的在上淡入、旧的保持不透明、盖住后才淡出）；所有贴图在第一次切换前预上传。
- 验证：逐帧截图 + 亮度曲线，透底会表现为中途的亮度凹陷。

**切过去时旁边多出来一块（一缕头发、半只胳膊），然后才消失**

- 原因：盖上再淡出时，旧姿势的轮廓比新姿势宽，新姿势盖满后那一块还露在外面，直到旧姿势淡掉。
- 解法：形变过渡——旧姿势先沿光流弯成新姿势的形状，交接时轮廓一致；再让旧姿势在被盖满后软淡出。

**形变过渡里道具被拖扁、手留下虚影**

- 原因：手从一处移到另一处（位移 100px 以上），光流找不到对应，把原来位置的东西一起拖走。
- 解法：轮廓检查（形变后轮廓缺失 > 5% 就拒），该对退回盖上再淡出；想要连续就补一张中间姿势。
- 注意：单看颜色误差分不出这种坏对，必须看轮廓。

**大动作切换时旧姿势的一部分在空中淡出（趴下睡觉时那颗头）**

- 原因：光流跟不上，退回了盖上再淡出；旧姿势露在新姿势轮廓外的部分没有东西盖，只能原地淡出。
- 解法：引导形变——告诉流水线「头从这个框到那个框」，头就沿路径走过去，换图时两颗头已经重合；再配慢速时序。

**某个姿势时躯干和桌面之间露出一条背景（椅背、墙）**

- 原因：截断线没落在桌沿上——brief 里写的截断线 y 是估的，比场景里的桌面远沿高；其他姿势的手臂和道具正好盖住那段空隙，露出躯干下沿的姿势（双手举起）才看得见。
- 解法：在底图上量桌面远沿，经配准换算（`canvas.cut_plate_y`，assemble 会核对），改 `cut_y` 和 brief，重出露躯干的姿势。

**喝咖啡时像有一个变形的人举着杯子从下面长上来**

- 原因：一步到位的大动作（手从书移到嘴边的杯子）用引导形变硬补，整片手臂按框被拉伸缩放。
- 解法：关键帧链——伸手、握杯、拿起、抬起、到胸前、喝，每步一小段，相邻帧用光流补；从任意姿势先回待机再开始，喝完倒着放回。

**拿起杯子那一下，桌上和手里同时有一只半透明的杯子**

- 原因：交接只靠 `hides` 交叉淡化，手里画的杯子和场景里那只不在同一个位置（生成方只看框、不看场景时会把杯子画得离身体更近）。
- 解法：握杯帧照版式图把杯子原位画进去、拿起帧竖直抬起，两帧标 `holds`（拿起帧再标 `hides`），`parts` 给场景里那只；
  `review/hold-*.jpg` 看红绿两条线。运行时场景的杯子跟着手走、到位才消失。

**链上每走一步，杯子 / 手臂闪出两份**

- 原因：这一步里杯子在身体前面移动了 100–200px，光流跟不上（轮廓检查看不出来，因为它在轮廓里面动），换图那一刻旧的和新的各露一份。
- 解法：①运行时关键帧步的换图窗口收窄到 42%–58%；②morph 的刚体块会把能用一个变换解释的物件整体搬过去；③剩下的（手臂跟着弯的那几步）
  只能再插帧，把每步降到 100px 以内。验证要在真运行时逐帧截，离线模拟图里也能看到同样的两份。

**切到写字 / 被摸头时，书在中段变成半透明的虚影**

- 原因：两张姿势手里的东西不一样（竖着的书 ↔ 平放的书 / 本子），形变能对上轮廓，对不上道具，道具只能在中段溶解。
- 解法：会停留的状态（写字）用链进去（书放低一半 → 书平放 → 写字）；反应（摸头、被戳）不换道具，只改脸和头，
  写字时另配变体（`poseIn`）。导演把所有链连成图，写字 ↔ 摸头这类变化会自动沿图走中间帧。

**打哈欠时嘴一下跳出来，眼睛同时啪地闭上**

- 原因：头不动、只有嘴张开，光流几乎为零，网格没有东西可带；整张脸的变化全挤在关键帧步 60ms 的换图窗口里。
  第一版哈欠图还把头仰了 25°，过渡中段一瞬双脸。
- 解法：①哈欠图只开嘴和眼的遮罩画，头的角度交给网格（抬几像素）；②拆成链：待机 → 半张嘴 → 张大，相邻两张用光流补；
  ③眼睛先用现成的眼睛图闭上（0.2s），链的每一步就只剩嘴；④链写 `swap: "wide"`，嘴在 25%–75% 之间慢慢出来。
  逐帧截一遍看：第二个案例改完是 19.4s 半眯、19.5s 闭眼、19.7s 起嘴慢慢张开、20.2s 张满。

**哈欠看着是扭的（嘴张开时脸像在拧）**

- 原因：链从睁眼的 anchor 直接接嘴，每一步眼睛和嘴同时在换；嘴只有两张（半张、张满），一步就要张开一半；眼睛图之间是硬切。
- 解法：①先在 anchor 上把眼睛淡成闭的，链从一张「闭眼、嘴没张」的帧起步，相邻两帧只差一点嘴；②嘴补到五张；
  ③眼睛图之间淡、不跳（`runtime.md`「眨眼」）；④时间按真实的猫打哈欠来（`creatures.md`「哈欠」）。第二个案例这样改完才顺。

**逐帧量出来的小跳（30fps 的 GIF 看不出，用户说「一顿一顿」）**

- 症状：`smooth.py` 的曲线是梳子齿，某几帧的变化是前后的 3–8 倍；看那一帧和上一帧的差图：
  - **整圈轮廓发红** = 两层叠画的软边。两张共用几何的网格叠着淡入，毛边 / 发丝的覆盖率叠成 a + a(1−a)，上层撤掉那一帧变回 a。
    出现在每次换眼睛的末尾、链每一步的末尾。解法：眼睛图在一张网格里混两张（`runtime.md`「眨眼」）；
    姿势之间在角色自己的图层里做加法溶解（`runtime.md`「在角色自己的图层里溶解」）
  - **一块（嘴、下颌）** = 那一步换图太快，或只有旧图有的部分在最后几帧才淡掉。解法同上的溶解；还陡就把变化最大的那一步放长
- 第二个案例：哈欠 120fps 量出 23 处，改完 0 处，每帧最大变化 0.79 → 0.37。
- 另一种：**被摸时整片背一帧跳一下**——呼吸幅度跟着「在不在被摸」一帧切换（1 倍 ↔ 1.3 倍）。幅度要随被摸的程度渐变，凡是乘在运动上的系数都一样。

**从别的姿势直接跳进一段动作的中间**

- 原因：导演只会「切到目标姿势」，不知道动作有起点。
- 解法：链总从待机出发；别的姿势显示着时先慢慢回到待机（`returnMs`）。

**过渡末尾啪地一下**

- 原因：形变结束那一帧直接把旧姿势 alpha 置 0，光流没弯到位的残余突然消失。
- 解法：新姿势完全不透明后（t ≥ 0.75），旧姿势在最后 20% 淡出。

## 眨眼

**一眨眼整张脸跳一下（眉毛、镜框、刘海挪了）**

- 原因：闭眼帧是单独生成的，几何漂了一两个像素。
- 解法：光流把闭眼帧对齐回睁眼帧（只移几何）。实测眼外变化 2–5% → 约 1%。

**对齐后闭着的睫毛线被拉成 S 形**

- 原因：光流在眼睛里把闭眼的眼睑硬对到睁眼的虹膜边缘上——它们不是同一样东西。
- 解法：眼带内不用局部光流，换成周围的整体运动（归一化卷积）；看 `blink-*.jpg` 的放大图确认。

**某个姿势眨眼时袖子 / 衣褶在闪**

- 原因：闭眼帧重画了纹理，不是几何漂移，对齐救不回。
- 解法：check 按眼外 5px 以上成块的变化拒掉（> 1%；整体变化 > 15% 也拒），这个姿势先不眨眼，重出闭眼帧。

## idle 运动

**人物呼吸时整个人变胖变瘦**

- 原因：整体缩放人物。
- 解法：网格按权重图变形，只抬胸肩和头，不缩放。

**被摸时整只像不倒翁一样前后摇**

- 原因 1：反应做成了整个容器绕脚底旋转（±2°）。原因 2：头的转动根放在了胸口、权重到眼睛才满，上半身跟着头一起转。
- 解法：铁律 8。整体只许变透明度；头绕脖子（下巴后面）转、根往上约十分之一就满权重，所以头整颗动、胸口不动；
  身体不微摆，要「摇」的只有头（蹭手约 3.5°，再叠 ±0.8° 的慢蹭）和尾巴尖。量法：逐帧光流，头、背、贴桌的尾巴三块各看位移，
  第二个案例改完头 12–17px、背和尾巴 1.5–2.5px（呼吸和尾尖）。

**猫跳上桌看着怪**

- 原因：同一场景里人是淡入淡出的，猫沿弧线跳上来、落地压扁——两种出场方式放在一起，跳的那个像贴纸被扔进来。
- 解法：出场退场跟同场景已有的角色一样（淡入淡出、同样的时长），只有画里真有起跳点和落点时才做位移。

**书（手里的东西）跟着一起呼吸**

- 原因：先乘了「不许动」再模糊，胸口的权重晕到了书上。
- 解法：先模糊呼吸权重，**之后**再乘「不许动」遮罩。

**帽兜 / 领口跟着头发一起飘**

- 原因：衣服和头发一样深，只按颜色认头发。
- 解法：头发只认脸周围一圈、下巴以上、和头顶连通的像素；再不行给这个姿势画头发遮罩。

**趴睡时胳膊在飘**

- 原因：头枕在深色袖子上，袖子和头发连成一片被认成头发。
- 解法：`hair.by_pose.<姿势> = {"mode": "none"}` 或给遮罩。

## 流水线

**重跑装配后眨眼又开始跳脸**

- 原因：对齐是原地改写闭眼帧，重跑装配把它还原成了未对齐的原图，而没人记得再跑对齐。
- 解法（本技能的结构）：每步从上一步的产物重新推导、只写自己的目录，`rig.py all` 永远按顺序跑完。

**遮罩编辑出来的帧整只大了一点、挪了几像素**

- 原因：输入的透明精灵图只把全透明像素压成了灰，半透明那一圈底下的光晕还在，模型把轮廓读大了；遮罩收得太紧时也会整张重画放大。
- 解法：每个像素按自己的 alpha 合成到中灰再送；候选先量全局相似变换（放大、平移）和对齐后的颜色变化，漂得少的优先；
  剩下的交给 align（`align_to` + `free`）。要部位变大不靠遮罩给空间，用局部放大镜变换（`generation.md`「模型做不到的三件事」）。

**形变的颜色误差被看不见的颜色拉高**

- 原因：误差按 RGBA 原始通道比，透明处（alpha≈0）底下存的颜色、半透明毛边下面的光晕都算进去了，屏幕上根本看不到它们。
- 解法：比**看得见的颜色**——每个像素先按自己的 alpha 合成到中灰（`rgb·a + 0.5·(1−a)`），再比；轮廓对不上交给 sil 去管。
  第二个案例改完：人物那一套没有一对的去留变了，猫的哈欠链各对降到 0.005–0.01。

**运行时列表和实际出货的文件对不上（请求 404、某对该形变却淡入淡出）**

- 原因：运行时代码里手写了「哪些姿势能形变」。
- 解法：运行时只读导出的清单 `rig.json`。

**大动作的形变场数值被截断**

- 原因：按「R = dx + 128」存，只能表示 ±127px。
- 解法：`rgb12` 格式（±256px、1/8px 精度）。

## 画质

**手机上人物和背景发糊、有锯齿**

- 原因：渲染分辨率封顶 2 倍，3 倍屏再被拉伸 1.5 倍。所有高密度手机都有，不只某一个品牌。
- 解法：按实际像素密度渲染（最多 3 倍、限总像素）。素材本身精度不够时要按更大尺寸出图，渲染倍率救不回来。

**下雨 / 调色时锯齿又回来**

- 原因：滤镜默认按 1 倍分辨率渲染。
- 解法：滤镜分辨率跟随画布。

## 验证

**截图里看不到问题，用户说在闪**

- 原因：闪烁只有 60ms，单张截图抓不到；浏览器窗口被遮挡时 `requestAnimationFrame` 停止，前台截图拿到的是旧画面。
- 解法：无头浏览器逐帧连拍（`capture.mjs`），看联系表和亮度曲线，发 GIF 给人看；只有一两帧的小跳要按 120fps 渲、用 `smooth.py` 量（SKILL.md 第 9 步）。

**动作做完回不到原样（停下来的那一刻，眼睛 / 头 / 轮廓和开始前差一点）**

- 原因：某个分量没收回（链停在倒数第二帧、眼睛淡到了别的图、头的位移留了尾巴）。直接比首尾帧看不出来，因为呼吸早已走到别的相位。
- 解法：渲一份去掉这个动作的参照片（同一脚本、同一帧率），`smooth.py --ref` 比末帧：应该逐像素一致（最大差 1 是取整）。

## 什么时候这套方法不够

网格形变 + 光流适合「同一个身体在原地做小到中等幅度的动作」。以下情况要换思路：

- 转身、侧身、站起来走动：需要真正的分层 rig（Spine / Live2D）或逐帧手绘，生成图做不到一致的分层；
- 手臂大幅换位置且要连续：补中间姿势，或接受淡入淡出；
- 口型同步、复杂表情混合：需要分层的五官，或专门的表情帧加眼 / 嘴局部对齐（可沿用 align 的思路，把眼带换成嘴带）。
